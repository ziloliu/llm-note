# 第五章 存储器和寄存器 — 寄存器详解与地址映射 笔记

---

## 一、存储器与寄存器的关系

### 1.1 STM32 存储空间组成

```
STM32 内部存储空间由三部分构成：

① SRAM（内存的一部分）
   → 地址：0x2000_0000 ~ 0x2000_FFFF（64 KB）
   → 作用：类似电脑内存，存储运行时数据
   → 易失性

② Flash（内存的一部分）
   → 地址：0x0800_0000 ~ 0x0807_FFFF（512 KB）
   → 作用：存储程序代码和全局常量
   → 非易失性

③ 片内外设寄存器
   → 地址：0x4000_0000 起（Block 2）
   → 作用：控制和配置所有外设模块
   → 本质：特殊存储单元（锁存器/触发器）

三者共同构成 STM32 的完整存储空间
```

### 1.2 与个人电脑的类比

```
┌──────────────────────────────────────────────────────────────┐
│  个人电脑（PC）：                                              │
│                                                                │
│  CPU 寄存器    ← 最快，数量最少，在 CPU 内部                     │
│  Cache(SRAM)   ← 高速缓存                                      │
│  内存(DRAM)    ← 主存，存放程序和数据                            │
│  硬盘(SSD/HDD) ← 外存，长期存储                                 │
│                                                                │
├──────────────────────────────────────────────────────────────┤
│  STM32 单片机：                                                │
│                                                                │
│  CPU 寄存器    ← Cortex-M3 内核寄存器（Block 7）                │
│  SRAM(64KB)    ← 运行时变量（相当于内存）                        │
│  Flash(512KB)  ← 程序代码 + 全局常量（相当于内存 + 硬盘）        │
│  外设寄存器    ← 各外设模块的配置/状态/数据寄存器（Block 2）      │
│                                                                │
└──────────────────────────────────────────────────────────────┘

注意：
  → STM32 中 SRAM + Flash 共同构成"内存"
  → Flash 既是"硬盘"（持久存储）也是"内存"的一部分（存放代码和常量）
  → 外设寄存器是独立的一类存储单元
```

## 二、什么是寄存器

### 2.1 两个层面的理解

```
寄存器有两重含义：

① 硬件层面
   → 底层由锁存器 / 触发器构成
   → 每一位 = 一个锁存器 / 触发器
   → 可存放一位 0 或 1
   → 多个锁存器/触发器组合 → 构成多位寄存器
   → 32 位寄存器 = 32 个锁存器/触发器

② 软件层面
   → 本质是一个指针指向的地址空间的别名
   → 对应存储器映射中的某一段固定地址
   → 通过指针操作该地址来读写寄存器
   → 寄存器名称 = 该地址的别名
```

### 2.2 硬件层面详解

```
寄存器的底层结构：

  每 1 位存储单元 = 1 个锁存器 / 触发器
  
  ┌──────────────────────────────────────────────┐
  │  SR 锁存器 / JK 触发器 / D 触发器             │
  │  → 可锁存高电平（1）或低电平（0）              │
  │  → 信号可接出连接到其他电路                     │
  └──────────────────────────────────────────────┘

  32 位寄存器 = 32 个锁存器/触发器并联

  ┌────┬────┬────┬────┬─────┬────┐
  │ b31│ b30│ b29│... │ b1  │ b0 │  ← 32 位寄存器
  └────┴────┴────┴────┴─────┴────┘
    ↑     ↑     ↑          ↑    ↑
   锁存器 锁存器 锁存器 ... 锁存器 锁存器
   
  每一位的信号都可接出到外部电路
```

### 2.3 不同类型寄存器的硬件功能

```
① 控制寄存器（CR — Control Register）
   → 每一位的输出连接到外设的功能控制电路
   → 写入 0 或 1 → 控制对应功能的开启/关闭
   → 例：CR1.MSTR = 1 → 设为主模式
   → 例：CR1.SPE  = 1 → 使能 SPI

② 状态寄存器（SR — Status Register）
   → 外部电路的状态信号输入到每一位
   → 读取寄存器 → 获取当前外设的工作状态
   → 例：SR.TXE  = 1 → 发送缓冲区为空
   → 例：SR.RXNE = 1 → 接收缓冲区有数据

③ 数据寄存器（DR — Data Register）
   → 纯粹存储一串二进制数据
   → 不直接控制外部电路，也不反映外部状态
   → 例：DR = 0x55 → 存储待发送的数据
```

## 三、寄存器与 SRAM/ROM 的异同

### 3.1 相同点

```
底层存储原理相同：
  → 都是用电子器件（锁存器/触发器/电容）存储 0 和 1
  → 都需要分配地址才能被 CPU 访问
  → 都存在于统一的 4 GB 地址空间中
```

### 3.2 不同点

| 对比项 | SRAM / ROM | 外设寄存器 |
|--------|-----------|-----------|
| 存储目的 | 存放程序和数据 | 控制外设 / 反映状态 / 传输数据 |
| 容量 | 大（KB ~ MB 级） | 小（每个外设仅十几个 32 位寄存器） |
| 地址分配 | 大块连续区域 | 每个外设一小段连续地址 |
| 访问意义 | 读写数据本身 | 每一位可能有特定的控制/状态含义 |
| 位置 | 独立存储区域 | 分布在各外设模块内部 |

## 四、寄存器映射

### 4.1 存储器映射 vs 寄存器映射

```
存储器映射（宏观划分）：
  → 把 4 GB 地址空间划分为 8 个 Block
  → 每个 Block 512 MB
  → 粗粒度："这个街区归 SRAM，那个街区归外设"
  → 类比：给街区分配门牌号范围

寄存器映射（细粒度划分）：
  → 在每个外设的地址范围内
  → 为每个具体的寄存器分配精确地址
  → 细粒度："这一户的门牌号是 CRL，隔壁是 CRH"
  → 类比：给每栋房子分配具体门牌号
```

### 4.2 寄存器地址的构成

```
每个外设寄存器的地址 = 基地址 + 偏移地址

以 GPIOA 为例：

  外设基地址          = 0x4000_0000（Block 2 起始）
  + APB2 偏移         = 0x0001_0000
  ──────────────────────────────
  APB2 外设基地址      = 0x4001_0000

  + GPIOA 偏移        = 0x0000_0800
  ──────────────────────────────
  GPIOA 基地址        = 0x4001_0800

  + CRL 偏移          = 0x00 → 0x4001_0800
  + CRH 偏移          = 0x04 → 0x4001_0804
  + IDR 偏移          = 0x08 → 0x4001_0808
  + ODR 偏移          = 0x0C → 0x4001_080C
  + BSRR 偏移         = 0x10 → 0x4001_0810
  + BRR 偏移          = 0x14 → 0x4001_0814
  + LCKR 偏移         = 0x18 → 0x4001_0818
```

### 4.3 地址对应关系图示

```
Block 2（0x4000_0000 起）外设地址分布：

0x4000_0000  ┌─────────────────────────┐
             │    APB1 外设（低速总线）   │
             │  TIM2 ~ TIM7             │
             │  USART2/3, UART4/5       │
             │  SPI2/I2S2, I2C1/2       │
             │  ...                     │
0x4001_0000  ├─────────────────────────┤
             │    APB2 外设（高速总线）   │
             │  AFIO:  0x4001_0000      │
             │  EXTI:  0x4001_0400      │
             │  GPIOA: 0x4001_0800  ←── │
             │  GPIOB: 0x4001_0C00      │
             │  ...                     │
             │  SPI1:  0x4001_3000      │
             │  USART1:0x4001_3800      │
             │  TIM1:  0x4001_2C00      │
             │  ...                     │
0x4002_3400  ├─────────────────────────┤
             │  其他外设（DMA, RCC 等）  │
0x4002_4400  ├─────────────────────────┤
             │    保留（未使用）          │
0x5FFF_FFFF  └─────────────────────────┘
```

## 五、寄存器在源码中的定义

### 5.1 定义的整体结构

```c
/* 定义过程分三步：

   ① 定义结构体类型（描述寄存器布局）
   ② 定义基地址宏（确定外设的固定地址）
   ③ 定义外设指针宏（将地址强转为结构体指针）
*/
```

### 5.2 第一步：定义结构体类型

```c
/* 描述 GPIO 外设所有寄存器的布局 */
typedef struct
{
    __IO uint32_t CRL;      /* 偏移 0x00：端口配置低寄存器 */
    __IO uint32_t CRH;      /* 偏移 0x04：端口配置高寄存器 */
    __IO uint32_t IDR;      /* 偏移 0x08：输入数据寄存器 */
    __IO uint32_t ODR;      /* 偏移 0x0C：输出数据寄存器 */
    __IO uint32_t BSRR;     /* 偏移 0x10：位设置/清除寄存器 */
    __IO uint32_t BRR;      /* 偏移 0x14：位清除寄存器 */
    __IO uint32_t LCKR;     /* 偏移 0x18：锁定寄存器 */
} GPIO_TypeDef;
```

```
关键点：
  → 每个成员都是 uint32_t（32 位），对应一个 32 位寄存器
  → 成员按寄存器的偏移地址顺序排列
  → 结构体成员紧密对齐，自动匹配偏移量
  → CRL 在 0x00，CRH 在 0x04，IDR 在 0x08 ...
```

### 5.3 第二步：定义基地址宏

```c
/* 层层叠加，从外设基地址到具体模块地址 */

#define PERIPH_BASE           ((uint32_t)0x40000000)
                    /* 外设基地址 = Block 2 起始地址 */

#define APB2PERIPH_BASE       (PERIPH_BASE + 0x10000)
                    /* APB2 外设基地址 = 0x40010000 */

#define GPIOA_BASE            (APB2PERIPH_BASE + 0x0800)
                    /* GPIOA 基地址 = 0x40010800 */
```

```
地址叠加过程：

  0x4000_0000  ← 外设基地址（PERIPH_BASE）
+ 0x0001_0000  ← APB2 偏移
─────────────
  0x4001_0000  ← APB2 外设基地址（APB2PERIPH_BASE）
+ 0x0000_0800  ← GPIOA 偏移
─────────────
  0x4001_0800  ← GPIOA 基地址（GPIOA_BASE）
```

### 5.4 第三步：定义外设指针宏

```c
/* 将基地址强转为结构体类型指针 */
#define GPIOA  ((GPIO_TypeDef *) GPIOA_BASE)
```

```
这一行代码的本质：

  GPIOA_BASE = 0x40010800（GPIOA 的基地址）
  
  (GPIO_TypeDef *) 0x40010800
  
  → 把地址 0x40010800 强制转换为 GPIO_TypeDef 类型的指针
  → GPIOA 就是一个指向 0x40010800 的 GPIO_TypeDef 指针
  → 通过 GPIOA->CRL 即可访问 0x40010800 处的寄存器
```

### 5.5 为什么不直接定义结构体变量

```
正常的做法（我们习惯的方式）：

  GPIO_TypeDef a;                // 定义结构体变量
  GPIO_TypeDef *p = &a;          // 取地址赋给指针
  p->CRL = 0x12345678;           // 通过指针操作

  问题：
  → 结构体变量 a 由系统自动分配内存地址
  → 地址会在 SRAM 中随机分配
  → 无法保证地址恰好等于 0x40010800
  → 寄存器的地址是硬件固定的，不能变动

实际的做法（STM32 库的方式）：

  #define GPIOA  ((GPIO_TypeDef *) 0x40010800)
  GPIOA->CRL = 0x12345678;

  优势：
  → 跳过结构体变量的定义
  → 直接将固定地址强转为结构体指针
  → 指针指向的地址就是硬件寄存器的真实地址
  → 通过指针操作 = 直接读写硬件寄存器
```

### 5.6 两种方式对比

```
┌──────────────────────────────────────────────────────────┐
│  方式一：正常结构体定义（不适用于寄存器）                    │
│                                                            │
│  GPIO_TypeDef a;                                           │
│  GPIO_TypeDef *p = &a;                                     │
│                                                            │
│  a 的地址 → 系统自动分配（在 SRAM 中随机位置）               │
│  p → 指向 SRAM 中的随机地址 ❌                              │
│  → 无法对应到 0x40010800（GPIOA 的真实地址）                │
├──────────────────────────────────────────────────────────┤
│  方式二：直接定义指针宏（STM32 库的做法）✅                   │
│                                                            │
│  #define GPIOA  ((GPIO_TypeDef *) 0x40010800)              │
│                                                            │
│  GPIOA → 直接指向 0x40010800                                │
│  GPIOA->CRL → 访问 0x40010800 处的寄存器 ✅                 │
│  GPIOA->CRH → 访问 0x40010804 处的寄存器 ✅                 │
│  → 地址完全由硬件决定，不会跑偏                              │
└──────────────────────────────────────────────────────────┘
```

## 六、结构体成员对齐与偏移地址

### 6.1 为什么成员必须都是 uint32_t

```c
typedef struct
{
    __IO uint32_t CRL;      /* 32 位 → 占 4 字节 → 偏移 0x00 */
    __IO uint32_t CRH;      /* 32 位 → 占 4 字节 → 偏移 0x04 */
    __IO uint32_t IDR;      /* 32 位 → 占 4 字节 → 偏移 0x08 */
    __IO uint32_t ODR;      /* 32 位 → 占 4 字节 → 偏移 0x0C */
    __IO uint32_t BSRR;     /* 32 位 → 占 4 字节 → 偏移 0x10 */
    __IO uint32_t BRR;      /* 32 位 → 占 4 字节 → 偏移 0x14 */
    __IO uint32_t LCKR;     /* 32 位 → 占 4 字节 → 偏移 0x18 */
} GPIO_TypeDef;
```

```
为什么不能定义成 uint16_t？

  假设错误定义：
    typedef struct {
        __IO uint16_t CRL;    /* 占 2 字节 → 偏移 0x00 */
        __IO uint16_t CRH;    /* 占 2 字节 → 偏移 0x02 ← 错误！应为 0x04 */
        ...
    } GPIO_TypeDef;

  问题：
    → CRH 的实际偏移地址是 0x04
    → 但如果定义为 uint16_t，结构体对齐后 CRH 的偏移是 0x02
    → 地址错位 → 访问错误的寄存器 → 灾难性后果

  正确做法：
    → 全部定义为 uint32_t（每个成员占 4 字节）
    → 自动对齐：第一个 0x00，第二个 0x04，第三个 0x08 ...
    → 与硬件寄存器的偏移地址完全吻合
    → 无需手动指定每个成员的偏移量
```

### 6.2 严丝合缝的对应关系

```
硬件寄存器布局：              结构体成员布局：

地址        寄存器             偏移      成员
──────────────────           ──────────────────
0x40010800  CRL               0x00      CRL      ← 自动对应
0x40010804  CRH               0x04      CRH      ← 自动对应
0x40010808  IDR               0x08      IDR      ← 自动对应
0x4001080C  ODR               0x0C      ODR      ← 自动对应
0x40010810  BSRR              0x10      BSRR     ← 自动对应
0x40010814  BRR               0x14      BRR      ← 自动对应
0x40010818  LCKR              0x18      LCKR     ← 自动对应

结构体成员紧密排列（每个 uint32_t 占 4 字节）
→ 无需手动指定偏移地址
→ 编译器自动按顺序分配 → 偏移量自动匹配
→ GPIOA->CRH 自动映射到 0x40010804
```

## 七、寄存器操作的完整链路

### 7.1 从代码到硬件的完整路径

```
源码操作：
  GPIOA->ODR |= (1 << 5);    // 置 PA5 为高电平

完整执行路径：

  ① GPIOA（宏定义）
     → 展开为 ((GPIO_TypeDef *) 0x40010800)
     → 得到指向 0x40010800 的结构体指针

  ② GPIOA->ODR（访问结构体成员）
     → ODR 偏移量 = 0x0C（结构体中第 4 个成员）
     → 实际地址 = 0x40010800 + 0x0C = 0x4001080C
     → 该地址对应 GPIOA_ODR 寄存器

  ③ |= (1 << 5)（位操作）
     → 读取 0x4001080C 处的当前值
     → 将第 5 位置 1
     → 写回 0x4001080C

  ④ 硬件响应
     → ODR 第 5 位对应的锁存器输出高电平
     → 该信号连接到 PA5 引脚的输出驱动电路
     → PA5 引脚输出 3.3V 高电平
```

### 7.2 流程图

```
  C 代码：GPIOA->ODR |= (1 << 5)
              │
              ▼
  编译器展开：((GPIO_TypeDef *)0x40010800)->ODR
              │
              ▼
  计算地址：0x40010800 + 0x0C = 0x4001080C
              │
              ▼
  CPU 执行：读取 0x4001080C → 修改第 5 位 → 写回 0x4001080C
              │
              ▼
  总线传输：通过 AHB/APB 总线访问外设地址空间
              │
              ▼
  硬件响应：ODR bit5 对应的锁存器输出高电平
              │
              ▼
  引脚输出：PA5 输出 3.3V → LED 亮
```

## 九、完整寄存器定义示例

### 9.1 以 SPI 为例

```c
/* ① 结构体类型定义 */
typedef struct
{
    __IO uint16_t CR1;      /* 偏移 0x00：控制寄存器 1 */
    uint16_t    RESERVED0;  /* 偏移 0x02：保留（补齐 32 位对齐） */
    __IO uint16_t CR2;      /* 偏移 0x04：控制寄存器 2 */
    uint16_t    RESERVED1;
    __IO uint16_t SR;       /* 偏移 0x08：状态寄存器 */
    uint16_t    RESERVED2;
    __IO uint16_t DR;       /* 偏移 0x0C：数据寄存器 */
    uint16_t    RESERVED3;
    __IO uint16_t CRCPR;    /* 偏移 0x10：CRC 多项式寄存器 */
    uint16_t    RESERVED4;
    __IO uint16_t RXCRCR;   /* 偏移 0x14：接收 CRC 寄存器 */
    uint16_t    RESERVED5;
    __IO uint16_t TXCRCR;   /* 偏移 0x18：发送 CRC 寄存器 */
    uint16_t    RESERVED6;
    __IO uint16_t I2SCFGR;  /* 偏移 0x1C：I2S 配置寄存器 */
    uint16_t    RESERVED7;
    __IO uint16_t I2SPR;    /* 偏移 0x20：I2S 预分频寄存器 */
    uint16_t    RESERVED8;
} SPI_TypeDef;

/* ② 基地址定义 */
#define SPI1_BASE  (APB2PERIPH_BASE + 0x3000)  /* 0x40013000 */
#define SPI2_BASE  (APB1PERIPH_BASE + 0x3800)  /* 0x40003800 */

/* ③ 外设指针定义 */
#define SPI1  ((SPI_TypeDef *) SPI1_BASE)
#define SPI2  ((SPI_TypeDef *) SPI2_BASE)
```

```
注意 SPI 的特殊之处：
  → SPI 的寄存器是 16 位的（非 32 位）
  → 每个寄存器后边都有 RESERVED 用于补齐到 32 位对齐
  → 保证每个寄存器占 4 字节地址空间
  → 偏移量仍然是 0x04、0x08、0x0C ... 递增
```

### 9.2 RESERVED 的作用

```
为什么 SPI 需要 RESERVED 而 GPIO 不需要？

GPIO 寄存器：
  → 每个寄存器都是 32 位（uint32_t）
  → 每个恰好占 4 字节 → 与 32 位总线宽度一致
  → 不需要补齐

SPI 寄存器：
  → 每个寄存器只有 16 位（uint16_t）
  → 只占 2 字节 → 不够 32 位总线宽度
  → 需要 RESERVED 补齐到 4 字节
  → 确保下一个寄存器的偏移地址正确

  例：
    CR1  → uint16_t @ 偏移 0x00（占 2 字节）
    R0   → uint16_t @ 偏移 0x02（补齐 2 字节）
    CR2  → uint16_t @ 偏移 0x04 ✅ 正确
```

## 十、CISC 与 RISC 架构（扩展知识）

```
CISC（Complex Instruction Set Computer，复杂指令集）：
  → 典型代表：x86 架构（Intel/AMD）
  → 指令丰富、功能复杂
  → CPU 内部寄存器数量相对较少

RISC（Reduced Instruction Set Computer，精简指令集）：
  → 典型代表：ARM 架构（STM32 使用）
  → 指令精简、执行效率高
  → 可配置更多的 CPU 内部寄存器

Cortex-M3 内核寄存器：
  → R0 ~ R12（通用寄存器）
  → SP（栈指针）
  → LR（链接寄存器）
  → PC（程序计数器）
  → xPSR（程序状态寄存器）
  → 这些是 CPU 内部寄存器，与外设寄存器不同
```

## 十一、关键概念速查

| 概念 | 说明 |
|------|------|
| 寄存器（硬件） | 由锁存器/触发器构成的存储单元，每位可存 0 或 1 |
| 寄存器（软件） | 指向固定地址的结构体指针的别名 |
| 32 位寄存器 | 由 32 个锁存器/触发器组成，占 4 字节地址空间 |
| 控制寄存器（CR） | 每位输出连接到外设控制电路，用于配置功能 |
| 状态寄存器（SR） | 外部电路状态输入，用于判断外设工作状态 |
| 数据寄存器（DR） | 存储待发送或已接收的数据 |
| 寄存器映射 | 为每个外设的每个寄存器分配精确的地址 |
| 存储器映射 | 为所有存储区域分配地址（宏观划分） |
| 基地址 | 外设寄存器区域的起始地址 |
| 偏移地址 | 某寄存器相对于基地址的地址偏移量 |
| 结构体对齐 | 结构体成员按声明顺序紧密排列，自动匹配偏移 |
| RESERVED | 用于补齐非 32 位寄存器到 32 位对齐的保留成员 |
| PERIPH_BASE | 外设基地址 = 0x4000_0000（Block 2 起始） |
| APB2PERIPH_BASE | APB2 外设基地址 = 0x4001_0000 |
| APB1PERIPH_BASE | APB1 外设基地址 = 0x4000_0000 |
| `__IO` | volatile 关键字，防止编译器优化对寄存器的读写 |
| CISC | 复杂指令集（x86），寄存器少 |
| RISC | 精简指令集（ARM），可配置更多寄存器 |

## 十二、常见问题

| 问题 | 解答 |
|------|------|
| 寄存器底层是什么？ | **锁存器 / 触发器**，每位一个，32 位寄存器 = 32 个 |
| 寄存器和 SRAM 有什么区别？ | 底层原理类似，但寄存器每位有**特定控制/状态功能** |
| 为什么不用结构体变量而用指针宏？ | 结构体变量由系统分配地址（SRAM 中随机），无法对应到硬件固定地址 |
| 为什么成员都定义为 uint32_t？ | 确保每个成员占 4 字节，偏移量自动匹配硬件寄存器地址 |
| RESERVED 有什么用？ | 补齐非 32 位寄存器到 32 位对齐，保证偏移地址正确 |
| GPIOA 的地址怎么算？ | PERIPH_BASE + 0x10000 + 0x0800 = **0x40010800** |
| `__IO` 是什么？ | volatile，告诉编译器每次都必须真正读写该地址，不能优化 |
| 存储器映射和寄存器映射的区别？ | 存储器映射是**宏观划分**（Block 级），寄存器映射是**微观划分**（单个寄存器级） |
| APB1 和 APB2 的区别？ | APB1 = 低速外设总线，APB2 = 高速外设总线，基地址不同 |
| 结构体指针强转访问寄存器的本质？ | 把硬件寄存器地址"假装"成结构体变量，用结构体语法操作硬件地址 |
