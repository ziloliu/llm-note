## 一、LCD 基础概念

### 1.1 什么是 LCD

LCD（Liquid Crystal Display，液晶显示器）是当前最主流的显示技术，广泛应用于电脑显示器、手机屏幕、平板电脑、电视等几乎所有电子设备。

- **核心优势**：薄、轻、省电
- **已全面取代**：早期的 CRT（阴极射线管）显示器

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

### 1.2 CRT 显示器（已淘汰）

CRT（Cathode Ray Tube，阴极射线管）是早期的显示技术，特点：

- 体积大、厚度大（后面有长长的"尾巴"）
- 理论上亮度更高、颜色饱和度更高
- 被淘汰原因：体积太大，无法用于便携式设备

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

## 二、LCD 接口驱动方式分类

LCD 显示屏的驱动/接口连接方式主要有 6 种：

1. **MCU 模式** ← 常用
2. **RGB 模式** ← 常用
3. SPI 模式
4. VSYNC 模式
5. MDDI 模式
6. DSI 模式

用得最多的是 **MCU 模式**和 **RGB 模式**。

**两种模式的共同点**：
- 都使用 RGB（红绿蓝）三原色表示每个像素的颜色
- 都需要显存（GRAM）存储所有像素的颜色数据
- 区别在于 **GRAM 放在哪里**

## 三、RGB 颜色表示原理

### 3.1 光学三原色（加法三原色）

RGB（Red 红、Green 绿、Blue 蓝）是光学三原色，用于发光设备（显示器、电视）。

**混合规则（加法混合）**：
- 不同颜色的光叠加 → 频率叠加 → 表现出新的颜色
- 所有光等比例混合 → 白光
- 全无 → 黑色（无光）

**常见混合示例**：
- R + G = 黄色（Yellow）
- R + B = 紫色/品红（Magenta）
- G + B = 青色/蓝绿（Cyan）
- R + G + B = 白色（White）

**为什么叫"加法"三原色**：光的混合是叠加，光越多越亮，全部叠加为白光（最亮）。

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

### 3.2 美术三原色（减法三原色）

美术三原色是 CMY（品红 Magenta、黄 Yellow、青 Cyan），用于反射设备（印刷、绘画）。

**混合规则（减法混合）**：
- 颜料吸收（减去）特定颜色的光，剩余颜色的光反射回来
- 品红 + 黄 = 吸收绿光和蓝光 → 只剩红光 → 红色
- 品红 + 黄 + 青 = 三种光全吸收 → 黑色

**为什么叫"减法"三原色**：混合颜料 = 叠加吸收，颜料越多吸收越多越暗，全部混合为黑色（全吸收）。

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

### 3.3 两种三原色对比

| 对比项 | 光学三原色（RGB） | 美术三原色（CMY） |
|--------|------------------|------------------|
| 基准颜色 | 红、绿、蓝 | 品红、黄、青 |
| 混合方式 | 加法（光叠加） | 减法（吸收叠加） |
| 全部混合 | 白色 | 黑色 |
| 应用场景 | 发光设备（显示器、电视） | 反射设备（印刷、绘画） |
| 原理 | 发出不同颜色的光 | 吸收特定颜色的光 |

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

## 四、显存（GRAM）

### 4.1 什么是 GRAM

GRAM（Graphic RAM，图形随机存取存储器）即显存，是一个存储矩阵，存储液晶屏上每一个像素点的颜色数据。

**示例**：320 × 240 分辨率的屏幕：
- 共有 320 × 240 = 76800 个像素点
- 每个像素点需要一组 RGB 数据
- 如果使用 RGB565（16 位）格式：总显存 = 76800 × 2 字节 = 153600 字节 ≈ 150 KB

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

### 4.2 GRAM 的位置决定了驱动模式

**关键问题**：GRAM（显存）放在哪里？

- **方案一：放在液晶驱动器内部** → MCU 模式
  - 主机通过接口发送命令和数据
  - 液晶驱动器内部处理并存储
- **方案二：放在主机侧（显卡）** → RGB 模式
  - 主机（CPU/GPU）处理所有图像数据
  - 直接输出 RGB 数据流给液晶

**两种模式的核心区别**：GRAM 的归属位置不同。

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

## 五、MCU 模式

### 5.1 基本原理

MCU 模式下，GRAM 集成在液晶驱动器（LCD 模块）内部，主机（MCU/单片机）只需发送命令和数据。

**工作流程**：
1. MCU 通过接口向液晶驱动器发送命令（如设置坐标）
2. MCU 通过接口向液晶驱动器发送颜色数据
3. 液晶驱动器接收数据，写入内部 GRAM
4. 液晶驱动器读取 GRAM 数据，驱动屏幕显示

**主机侧的工作**：只需要发送命令和数据，不需要集成显存，功能简单，适合 MCU/单片机。

**液晶驱动器的工作**：接收命令和数据，内部集成 GRAM 存储像素数据，将数据转换为驱动像素的信号，驱动屏幕显示。

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

### 5.2 与 FSMC 的结合

MCU 模式下的液晶控制可以用 FSMC 实现！

**原理**：
- GRAM 本质是一个存储器
- 液晶驱动器的接口本质上就是存储器接口
- FSMC 可以扩展外部存储器
- 因此 FSMC 可以控制 LCD

**具体做法**：
- 将 LCD 模块的接口连接到 FSMC 的地址线、数据线、控制线
- LCD 的 RS（寄存器选择）连接 FSMC 的 A10
- 通过不同的地址区分写命令和写数据
- CPU 像访问存储器一样访问 LCD

**优势**：
- 利用 FSMC 的自动协议转换
- 无需手动编写通信协议
- 速度快（并行传输）
- 配置简单

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

### 5.3 MCU 模式的特点

**优势**：
- 主机侧（MCU）工作简单，只需发送命令和数据
- 不需要集成显存
- 适合单片机等资源有限的设备
- 可以用 FSMC 简化控制

**劣势**：
- 液晶驱动器处理能力有限
- 显示速度相对较慢
- 适合静态图片或简单画面
- 动态画面或大屏幕可能不够流畅

**适用场景**：
- 嵌入式设备的小屏幕显示
- 静态信息展示（菜单、参数、文字）
- 简单图形界面
- 分辨率较低的屏幕（如 320×240、480×320）

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

## 六、RGB 模式

### 6.1 基本原理

RGB 模式下，GRAM 集成在主机侧（显卡/GPU），主机（CPU/GPU）处理所有图像数据，直接输出每个像素的 RGB 数据流给液晶。

**工作流程**：
1. CPU/GPU 处理图像数据，写入显卡的显存（GRAM）
2. 显卡从 GRAM 读取数据
3. 显卡产生 RGB 数据流 + 同步信号（行同步、帧同步）
4. RGB 数据流直接传输给液晶面板
5. 液晶面板直接驱动显示

**主机侧的工作**：CPU/GPU 完成所有图像处理，显卡集成 GRAM（显存），产生 RGB 数据和同步信号，工作量大但处理能力强。

**液晶面板的工作**：只负责接收 RGB 数据流，直接驱动像素显示，不做数据处理和存储。

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

### 6.2 显卡的组成

显卡的核心组成：

1. **GPU**（Graphics Processing Unit，图形处理单元）
   - 专门处理图像数据的处理器
   - 大规模并行计算能力强
   - 适合处理海量像素数据
2. **显存（GRAM）**
   - 存储所有像素的颜色数据
   - 容量越大 → 可支持更高分辨率和更复杂的图像
3. **LCD 控制器**
   - 从显存读取数据
   - 产生 RGB 数据流和同步信号
   - 输出给液晶面板

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

### 6.3 独立显卡 vs 集成显卡

**集成显卡**：
- GPU 集成在 CPU 内部
- 显存可能与内存共享
- 性能较弱，功耗低
- 适合日常办公和轻度图形处理

**独立显卡**：
- GPU 独立芯片
- 专用显存（GDDR5/GDDR6 等）
- 性能强大，功耗高
- 适合游戏、3D 渲染、AI 计算等

**应用场景**：
- 大型游戏 → 需要高性能独立显卡
- AI 训练/推理 → 显卡的并行计算能力
- 视频剪辑/3D 建模 → 显卡加速
- 日常办公 → 集成显卡即可

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

### 6.4 RGB 模式的特点

**优势**：
- 液晶面板只负责显示，响应快
- 适合大屏幕、高分辨率
- 适合动态画面（视频、动画）
- 主机侧处理能力强

**劣势**：
- 需要专用的显卡/LCD 控制器
- 需要集成显存
- 主机侧资源需求大
- 不适合资源有限的单片机

**适用场景**：
- 电脑显示器
- 电视
- 高分辨率、高刷新率的屏幕
- 需要流畅动态画面的场景

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

## 八、MCU 模式下 LCD 的控制方式

### 8.1 控制流程

MCU 控制 LCD 显示的基本流程：

1. **初始化 LCD 驱动器**
   - 发送初始化命令序列
   - 配置显示参数（分辨率、颜色格式等）
2. **设置显示区域**
   - 发送命令设置 GRAM 的写入坐标
   - 指定要写入的像素位置（行列地址）
3. **写入颜色数据**
   - 将 RGB 颜色数据写入 GRAM
   - 每写入一个数据，GRAM 地址自动递增
   - 连续写入多个像素的颜色数据
4. **液晶驱动器自动刷新显示**
   - 从 GRAM 读取数据
   - 驱动对应像素点显示颜色

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

### 8.2 FSMC 控制 LCD 的地址映射

FSMC 连接 LCD 模块时：
- **写命令**：访问地址 0x6C00_0000（A10 = 0 → RS = 0 → 命令）
- **写数据**：访问地址 0x6C00_0800（A10 = 1 → RS = 1 → 数据）

**示例代码**：
```c
// 写命令
*(volatile uint16_t *)0x6C000000 = 0x002C;  // 发送命令码

// 写数据
*(volatile uint16_t *)0x6C000800 = 0xF800;  // 写入红色 RGB565
```

**效果**：CPU 访问特定地址 → FSMC 自动转换为 LCD 接口的通信协议 → LCD 驱动器接收命令或数据 → 数据写入内部 GRAM → 屏幕显示对应颜色。

📄 [原文01: LCD原理与接口分类](../raw/嵌入式开发/LCD/01_LCD原理与接口分类.md)

## 九、TFT LCD 液晶模块

### 9.1 TFT LCD 概述

TFT（Thin Film Transistor，薄膜晶体管）LCD 是当前嵌入式设备中使用最广泛的液晶显示技术。

**原理**：每个像素点由薄膜晶体管驱动，将电信号（RGB 数据）转换为对薄膜晶体管的控制，薄膜晶体管驱动像素点显示不同颜色。

**特点**：
- 优秀的显示性能（颜色、对比度、亮度）
- 低功耗
- 广泛应用于嵌入式电子设备

📄 [原文02: 液晶模块与控制器详解](../raw/嵌入式开发/LCD/02_液晶模块与控制器详解.md)

### 9.2 Z350IT002 液晶模块

Z350IT002 是一款 TFT LCD 液晶模块，基本参数：

| 参数 | 值 |
|------|-----|
| 型号 | Z350IT002 |
| 类型 | TFT LCD（薄膜晶体管液晶显示器） |
| 分辨率 | **320 × 480** |
| 横向像素 | 320 个 |
| 纵向像素 | 480 个 |
| 接口模式 | **MCU 模式**（I80 / 8080 总线标准） |
| 数据宽度 | **16 位** |
| 控制器芯片 | **ILI9486** |

**分辨率说明**：320 × 480 分辨率，总像素数 153600 个，相当于早期标清视频的分辨率，适合中小尺寸的嵌入式显示需求。

**底层驱动结构**：
- 960 个 Source（源极）驱动：驱动横向像素（320 列 × 3 RGB）
- 480 个 Gate（栅极）驱动：驱动纵向像素（480 行）
- 每个像素点由 R、G、B 三个子像素组成

## 十、ILI9486 液晶控制器芯片

### 10.1 芯片概述

ILI9486 是台湾 ILITEC（伊利科技）公司生产的 LCD 控制器芯片，是最流行的 LCD 控制器芯片之一。

**功能**：
- 驱动中小型尺寸的 TFT LCD
- 支持分辨率：320 × 480
- 内含源极驱动器（Source Driver）和栅极驱动器（Gate Driver）
- 内含显存（GRAM）
- 支持多种接口类型

📄 [原文02: 液晶模块与控制器详解](../raw/嵌入式开发/LCD/02_液晶模块与控制器详解.md)

### 10.2 支持的接口类型

ILI9486 支持多种接口类型：

1. **并行 CPU 数据总线接口（8080 总线标准）**
   - 支持 8 位、9 位、16 位、18 位数据宽度
   - MCU 模式
2. **RGB 标准数据总线**
   - 用于视频图像展示
   - RGB 模式
3. **SPI 串行外设接口**
   - 支持 3 线和 4 线 SPI
   - 串行数据传输
4. **高速串行接口**
   - 支持 MIPI DSI 链路
   - 最高 500 Mbps
5. **MDDI 接口**
   - Mobile Display Digital Interface

**我们使用的方式**：IM[2:0] = 010，8080 总线标准（MCU 模式），16 位数据总线宽度，数据引脚 D[15:0]。

📄 [原文02: 液晶模块与控制器详解](../raw/嵌入式开发/LCD/02_液晶模块与控制器详解.md)

### 10.3 接口选择（IM 位配置）

ILI9486 通过 IM[2:0] 引脚选择接口模式：

| IM[2:0] | 接口类型 |
|---------|----------|
| 000 | 并行 RGB |
| 001 | 串行 RGB |
| 010 | 8080 系统接口（16 位）← 我们使用这个 |
| 011 | 保留 |
| 100 | 3 线 SPI（9 位） |
| 101 | 3 线 SPI（16 位） |
| 110 | 4 线 SPI（8 位） |
| 111 | 4 线 SPI（16 位） |

硬件上 IM 引脚已固定为 010，确定使用 8080 系统接口，16 位数据总线，数据引脚 D[15:0]。

## 十一、MCU 模式与 8080 总线标准

### 11.1 MCU 模式的本质

MCU 模式的核心特征：
- 显存（GRAM）集成在液晶控制器内部
- MCU（单片机）只需发送命令和数据
- 控制器接收数据 → 写入内部 GRAM → 驱动显示

**为什么叫 MCU 模式**：最早由 Intel 提出的 8080 总线标准，专为微控制器（MCU）设计，MCU 操作简单，适合资源有限的单片机，因此称为 MCU 模式 / I80 模式 / 8080 时序。

📄 [原文02: 液晶模块与控制器详解](../raw/嵌入式开发/LCD/02_液晶模块与控制器详解.md)

### 11.2 8080 总线标准

8080 总线标准（Intel 8080 Bus Standard）是最早由 Intel 提出的并行总线标准，用于微处理器与外部设备之间的并行数据传输。

**核心信号**：
- **CS**：片选信号
- **RS**：寄存器选择（命令/数据选择）
- **RD**：读使能
- **WR**：写使能
- **D[15:0]**：16 位数据总线

**与 FSMC 的对应关系**：
- 8080 总线标准 ≈ FSMC 扩展存储器的方式
- 可以直接用 FSMC 实现 8080 时序
- 无需手动编写通信协议

📄 [原文02: 液晶模块与控制器详解](../raw/嵌入式开发/LCD/02_液晶模块与控制器详解.md)

### 11.3 用 FSMC 实现 8080 时序

**核心思路**：将 LCD 的显存（GRAM）视为一个扩展的存储器，使用 FSMC 连接 LCD 模块，CPU 像访问内存一样访问 LCD。

**连接方式**：
- LCD 的数据线 D[15:0] → FSMC 数据线
- LCD 的 CS → FSMC NE（片选）
- LCD 的 RS → FSMC A10（命令/数据选择）
- LCD 的 RD → FSMC NOE（读使能）
- LCD 的 WR → FSMC NWE（写使能）

**地址映射**：
- 写命令地址：A10 = 0 → 0x6C00_0000
- 写数据地址：A10 = 1 → 0x6C00_0800

**操作方式**：
- 写命令：`*(volatile uint16_t *)0x6C000000 = command;`
- 写数据：`*(volatile uint16_t *)0x6C000800 = data;`

## 十二、ILI9486 命令操作

### 12.1 命令与数据的交互

ILI9486 的操作方式类似 Flash/W25Q32 的指令交互：
- 先发送命令码（告诉控制器要做什么操作）
- 再发送数据（操作的具体参数或颜色数据）

**常见操作**：
- 设置显示区域（窗口）
- 设置 GRAM 写入坐标
- 写入像素颜色数据
- 配置显示参数（方向、颜色格式等）
- 读取状态/数据

命令码在芯片手册第 8 章有详细定义。

📄 [原文02: 液晶模块与控制器详解](../raw/嵌入式开发/LCD/02_液晶模块与控制器详解.md)

### 12.2 区域写入操作

ILI9486 支持指定显示区域后连续写入数据：

1. **发送命令设置窗口范围**
   - 指定起始行、结束行、起始列、结束列
   - 定义要写入的矩形区域
2. **发送写入 GRAM 命令**
   - 通知控制器接下来发送的是颜色数据
3. **连续发送颜色数据**
   - 每个数据对应一个像素点的颜色
   - GRAM 地址自动递增
   - 按行优先顺序填充整个区域

**效果**：不需要逐个像素点指定坐标，一次设置区域，连续写入数据，控制器自动管理 GRAM 地址，操作简单高效。

## 十三、RGB565 颜色格式

### 13.1 为什么用 16 位表示颜色

16 位数据总线每次传输 16 位数据，16 位需要分配给 R、G、B 三种颜色：16 ÷ 3 = 5.33... 无法均分，解决方案：5 + 6 + 5 = 16 位。

**为什么绿色多一位**：人眼对绿色最敏感，可见光谱中绿色处于中间频率段，人眼对绿色的捕获能力最强，给绿色多分配 1 位 → 更细腻的绿色层次。

📄 [原文02: 液晶模块与控制器详解](../raw/嵌入式开发/LCD/02_液晶模块与控制器详解.md)

### 13.2 RGB565 格式定义

RGB565 格式（16 位）：

| 位 | [15:11] | [10:5] | [4:0] |
|---|---------|--------|-------|
| 颜色 | R | G | B |
| 位数 | 5 位 | 6 位 | 5 位 |

**颜色表示能力**：
- 红色：2^5 = 32 级
- 绿色：2^6 = 64 级
- 蓝色：2^5 = 32 级
- 总颜色数：32 × 64 × 32 = 65536 种颜色
- 也称为 65K 色或 16 位真彩色

📄 [原文02: 液晶模块与控制器详解](../raw/嵌入式开发/LCD/02_液晶模块与控制器详解.md)

### 13.3 常见颜色的 RGB565 值

| 颜色 | R(5位) | G(6位) | B(5位) | RGB565 值 |
|------|--------|--------|--------|-----------|
| 白色 | 11111 | 111111 | 11111 | 0xFFFF |
| 黑色 | 00000 | 000000 | 00000 | 0x0000 |
| 红色 | 11111 | 000000 | 00000 | 0xF800 |
| 绿色 | 00000 | 111111 | 00000 | 0x07E0 |
| 蓝色 | 00000 | 000000 | 11111 | 0x001F |
| 黄色 | 11111 | 111111 | 00000 | 0xFFE0 |
| 青色 | 00000 | 111111 | 11111 | 0x07FF |
| 品红 | 11111 | 000000 | 11111 | 0xF81F |

📄 [原文02: 液晶模块与控制器详解](../raw/嵌入式开发/LCD/02_液晶模块与控制器详解.md)

### 13.4 颜色值计算方法

将 RGB888（24 位）转换为 RGB565（16 位）：

**转换公式**：
- R5 = R8 >> 3（取高 5 位）
- G6 = G8 >> 2（取高 6 位）
- B5 = B8 >> 3（取高 5 位）
- RGB565 = (R5 << 11) | (G6 << 5) | B5

**示例**：纯红色 (255, 0, 0)
- R5 = 255 >> 3 = 31 = 0x1F
- G6 = 0 >> 2 = 0
- B5 = 0 >> 3 = 0
- RGB565 = (0x1F << 11) | (0 << 5) | 0 = 0xF800

## 十四、系统整体架构

### 14.1 完整控制链路

```
┌──────────┐   AHB 总线   ┌───────┐   地址/数据/控制线   ┌──────────────┐
│  STM32   │──────────────→│ FSMC  │────────────────────→│ ILI9486      │
│  (CPU)   │              │       │                      │ (LCD 控制器)  │
└──────────┘              └───────┘                      ├──────────────┤
                                                         │  GRAM (显存)  │
                                                         ├──────────────┤
                                                         │ 源极/栅极驱动 │
                                                         ├──────────────┤
                                                         │  TFT LCD 面板 │
                                                         │  320 × 480    │
                                                         └──────────────┘
```

**控制流程**：
1. CPU 通过 AHB 总线发送地址和数据
2. FSMC 转换为 8080 总线协议
3. 通过地址线、数据线、控制线连接 ILI9486
4. ILI9486 接收命令/数据，写入内部 GRAM
5. ILI9486 从 GRAM 读取数据
6. 源极/栅极驱动器驱动 TFT LCD 面板显示

📄 [原文02: 液晶模块与控制器详解](../raw/嵌入式开发/LCD/02_液晶模块与控制器详解.md)

### 14.2 FSMC 与 LCD 的连接信号

| FSMC 信号 | LCD（ILI9486）信号 | 功能 |
|-----------|-------------------|------|
| D[15:0] | D[15:0] | 16 位数据线 |
| NE | CS | 片选信号（低有效） |
| A10 | RS | 命令/数据选择 |
| NOE | RD | 读使能（低有效） |
| NWE | WR | 写使能（低有效） |

**RS（寄存器选择）**：
- RS = 0（A10 = 0）→ 传输命令
- RS = 1（A10 = 1）→ 传输数据

📄 [原文02: 液晶模块与控制器详解](../raw/嵌入式开发/LCD/02_液晶模块与控制器详解.md)

### 14.3 地址映射

连接到 Bank 1 的某个子区（如 NE4）：
- 写命令地址：0x6C00_0000（A10 = 0 → RS = 0）
- 写数据地址：0x6C00_0800（A10 = 1 → RS = 1）

**操作方式**：
```c
// 发送命令
*(volatile uint16_t *)0x6C000000 = 0x002C;  // 写 GRAM 命令

// 写入像素颜色数据
*(volatile uint16_t *)0x6C000800 = 0xF800;  // 红色
*(volatile uint16_t *)0x6C000800 = 0x07E0;  // 绿色
*(volatile uint16_t *)0x6C000800 = 0x001F;  // 蓝色
```

**效果**：CPU 认为自己在访问内存，FSMC 自动转换为 8080 协议，ILI9486 接收命令和数据，数据写入 GRAM → 驱动像素显示。

## 十五、与扩展 SRAM 的对比

### 15.1 相同点

FSMC 扩展 SRAM vs FSMC 控制 LCD 的相同点：
- 都使用 FSMC 进行地址映射
- 都通过地址线、数据线、控制线连接
- 都使用 16 位数据宽度
- CPU 都像访问内存一样操作
- 都位于 Bank 1 的某个子区
- GPIO 配置方式相同（复用推挽输出）
- BCR/BTR 寄存器配置方式相同

📄 [原文02: 液晶模块与控制器详解](../raw/嵌入式开发/LCD/02_液晶模块与控制器详解.md)

### 15.2 不同点

FSMC 扩展 SRAM vs FSMC 控制 LCD 的不同点：
- SRAM 是真正的存储器，LCD 的 GRAM 是显存
- SRAM 直接存储数据，LCD 需要先发命令再发数据
- LCD 有 RS 信号（命令/数据选择），SRAM 没有
- LCD 通过 A10 区分命令和数据，SRAM 不需要
- LCD 最终驱动像素显示，SRAM 纯粹存储数据

## 十七、LCD 硬件电路设计与引脚连接

### 17.1 LCD 显示案例目标

使用 STM32 的 FSMC 模块控制液晶屏：
- 显示英文字符
- 显示汉字
- 显示自定义图形/信息

**核心思路**：将 LCD 的显存（GRAM）视为 FSMC 扩展的存储器，通过 FSMC 发送命令和数据，控制 ILI9486 驱动 320×480 的 TFT LCD 显示。

📄 [原文03: 硬件电路设计与引脚连接](../raw/嵌入式开发/LCD/03_硬件电路设计与引脚连接.md)

### 17.2 LCD 背光光源

LCD 显示屏需要背光光源才能看到画面：

**① CCFL（冷阴极射线管）背光（已淘汰）**
- 本质是荧光管/灯管
- 体积大、占空间
- 亮度效率不高
- 已被 LED 背光取代

**② LED（发光二极管）背光（当前主流）**
- 体积小、薄
- 亮度高、效率高
- 功耗低
- 当前 LCD 普遍使用

**工作原理**：LED 提供白色背光光源，TFT 薄膜晶体管控制每个像素点的颜色比例，相当于白光经过滤色后呈现出不同的颜色。

📄 [原文03: 硬件电路设计与引脚连接](../raw/嵌入式开发/LCD/03_硬件电路设计与引脚连接.md)

### 17.3 LCD 模块引脚连接

LCD 模块引脚分类：

1. **数据总线**：D0 ~ D15（16 根）→ FSMC 数据线直连
2. **控制信号**：
   - CS（片选）→ NE4
   - RS（命令/数据选择）→ A10
   - RD（读使能）→ NOE
   - WR（写使能）→ NWE
   - RST（复位）→ PG15（GPIO）
3. **背光控制**：
   - LEDA → 3.3V（背光电源）
   - LEDK → PB0（背光亮度控制，GPIO）
4. **电源**：VCC（3.3V）、GND
5. **触摸屏（未使用）**：X+、X-、Y+、Y-

📄 [原文03: 硬件电路设计与引脚连接](../raw/嵌入式开发/LCD/03_硬件电路设计与引脚连接.md)

### 17.4 各引脚功能详解

**① 数据总线 D0 ~ D15**
- LCD 的 D0 ~ D15 直连 FSMC 的 D[15:0]
- 16 位并行数据传输
- 传输命令码、地址数据、RGB 颜色数据
- 双向传输（读/写操作）

**② 片选信号 CS**
- CS 连接 FSMC 的 NE4
- 低电平有效
- 对应 Bank1-4 地址范围：0x6C00_0000 ~ 0x6FFF_FFFF
- 选中 LCD 模块进行通信

**③ RS 信号（命令/数据选择）**
- RS 连接 FSMC 的 A10
- 这不是真正的地址线功能，而是用于区分命令和数据
- RS = 0（A10 = 0）→ 当前传输的是命令（Command）
- RS = 1（A10 = 1）→ 当前传输的是数据（Data）
- 对应的 GPIO 引脚：PJ0

**④ 读写控制信号**
- RD（Read）→ 连接 FSMC 的 NOE，读使能，低电平有效
- WR（Write）→ 连接 FSMC 的 NWE，写使能，低电平有效

**⑤ 复位信号 RST**
- RST 连接 PG15（通用 GPIO，非 FSMC 复用）
- 低电平有效
- 拉低 → LCD 控制器复位
- 拉高 → 正常工作
- 初始化时需要进行复位操作
- PG15 没有 FSMC 复用功能，需要单独配置为通用推挽输出模式

**⑥ 背光控制**
- LEDA（背光阳极）：直接连接 3.3V 电源，提供背光 LED 的供电
- LEDK（背光阴极）：连接 PB0（LCD_BG，通用 GPIO），用于调节背光亮度，可通过 PWM 或高低电平控制亮度
- PB0 没有 FSMC 复用功能，需要单独配置为通用推挽输出模式

📄 [原文03: 硬件电路设计与引脚连接](../raw/嵌入式开发/LCD/03_硬件电路设计与引脚连接.md)

### 17.5 完整引脚连接表

**FSMC 复用引脚**：

| LCD 信号 | FSMC 信号 | STM32 GPIO | 功能 |
|----------|-----------|------------|------|
| D0 ~ D15 | D[15:0] | FSMC 复用引脚 | 16 位数据总线 |

### 17.6 RS 信号与命令/数据传输机制

**为什么只需要 A10**：LCD 模块没有真正的地址线，不像 SRAM 那样有 19 根地址引脚，只连接了一根线：A10 → RS。A10 的作用不是寻址，而是区分命令和数据：
- RS = 0（A10 = 0）→ 传输命令
- RS = 1（A10 = 1）→ 传输数据

**命令和数据都通过 D[15:0] 数据总线传输**：先发命令（告知操作类型），再发数据（地址参数或颜色数据），命令和数据分时复用同一组数据线。

**命令/数据传输流程**：向某个像素点写入红色
1. 发送"设置坐标"命令（RS = 0 → 写命令）→ 告诉 LCD 控制器要操作哪个像素位置
2. 发送坐标数据（RS = 1 → 写数据）→ 传输行地址和列地址，指明要写入的 GRAM 位置
3. 发送"写 GRAM"命令（RS = 0 → 写命令）→ 告诉 LCD 控制器接下来要写入颜色数据
4. 发送颜色数据（RS = 1 → 写数据）→ 传输 16 位 RGB565 颜色值（如 0xF800 = 红色），数据写入 GRAM → 驱动像素显示

📄 [原文03: 硬件电路设计与引脚连接](../raw/嵌入式开发/LCD/03_硬件电路设计与引脚连接.md)

### 17.7 与 SPI 控制 Flash 的类比

**控制 W25Q32 Flash（SPI）**：
1. CS 拉低
2. 发送指令码（如 0x02 页写指令）
3. 发送 24 位地址
4. 发送数据
5. CS 拉高

**控制 ILI9486 LCD（FSMC）**：
1. FSMC 自动片选（NE4）
2. RS = 0 → 发送命令码
3. RS = 1 → 发送地址/参数数据
4. RS = 0 → 发送写 GRAM 命令
5. RS = 1 → 发送颜色数据

**相似之处**：都是先发指令，再发数据，都有命令和数据的区分机制，都通过数据线传输内容。

**不同之处**：Flash 用 SPI（串行），LCD 用 FSMC（并行），Flash 地址通过数据线依次发送，LCD 用 RS 信号区分，FSMC 自动管理时序，CPU 负担更轻。

📄 [原文03: 硬件电路设计与引脚连接](../raw/嵌入式开发/LCD/03_硬件电路设计与引脚连接.md)

### 17.8 地址映射

**FSMC 地址空间**：LCD 连接 NE4 → Bank1-4，地址范围：0x6C00_0000 ~ 0x6FFF_FFFF。

**写命令地址**：0x6C00_0000（A10 = 0 → RS = 0）
**写数据地址**：0x6C00_0800（A10 = 1 → RS = 1）

**16 位数据宽度下的地址推导**：
- FSMC_A[N] = HADDR[N+1]（交叉连接）
- A10 = HADDR[11]
- HADDR[11] = 0 → 地址 = 0x6C00_0000（写命令）
- HADDR[11] = 1 → 地址 = 0x6C00_0800（写数据）
- 2^11 = 0x800

**与扩展 SRAM 的对比**：
- 扩展 SRAM（NE3）：地址范围 0x6800_0000 ~ 0x6BFF_FFFF，19 根地址线 → 512K 个存储单元，直接读写数据
- 控制 LCD（NE4）：地址范围 0x6C00_0000 ~ 0x6FFF_FFFF，只用 A10 区分命令/数据，先发命令，再发数据，命令中包含操作类型和参数

**相同点**：都使用 FSMC 进行地址映射，都在 Bank 1 内，都使用 16 位数据宽度，BCR/BTR 配置方式相同，GPIO 配置方式相同（复用推挽输出）。

📄 [原文03: 硬件电路设计与引脚连接](../raw/嵌入式开发/LCD/03_硬件电路设计与引脚连接.md)

### 17.9 LCD 操作的整体流程

**初始化流程**：
1. 配置 FSMC（BCR + BTR 寄存器或 CubeMX 配置）
2. 配置 GPIO（FSMC 复用引脚 + RST/PB0 通用引脚）
3. 复位 LCD（RST 引脚拉低再拉高）
4. 开启背光（PB0 拉高）
5. 发送 ILI9486 初始化命令序列（配置显示参数、电源和时序参数）
6. 清屏（将所有像素写入黑色/白色）

**显示字符流程**：
1. 设置显示窗口（指定行列范围）→ 发送设置窗口命令 + 行列坐标数据
2. 发送写 GRAM 命令 → 通知控制器接下来是颜色数据
3. 逐像素写入颜色数据 → 根据字模数据，像素为 1 写前景色，为 0 写背景色，连续发送 16 位 RGB565 颜色数据，GRAM 地址自动递增
4. 完成字符显示

📄 [原文03: 硬件电路设计与引脚连接](../raw/嵌入式开发/LCD/03_硬件电路设计与引脚连接.md)

### 17.10 LCD_RST 和 LCD_BG 的 GPIO 配置

**RST（复位引脚）**：
- 引脚：PG15
- 模式：通用推挽输出
- 功能：LCD 控制器复位
- 操作：初始化时 PG15 输出低电平 → 复位，延时一段时间，PG15 输出高电平 → 正常工作

**BG（背光控制引脚）**：
- 引脚：PB0
- 模式：通用推挽输出
- 功能：控制背光亮度
- 操作：PB0 输出高电平 → 背光开启，PB0 输出低电平 → 背光关闭，可使用 PWM 控制亮度（高级应用）

📄 [原文03: 硬件电路设计与引脚连接](../raw/嵌入式开发/LCD/03_硬件电路设计与引脚连接.md)

### 17.11 LCD 背光原理

**LED 背光工作方式**：
- LEDA（阳极）连接 3.3V 电源
- LEDK（阴极）连接 PB0 控制引脚

**亮度控制**：
- PB0 输出低电平 → LED 导通 → 背光亮
- PB0 输出高电平 → LED 截止 → 背光灭
- PWM 调节 → 控制 LED 导通时间比例 → 调节亮度

**显示原理**：LED 发出白色背光，白光穿过液晶层，TFT 薄膜晶体管控制每个像素的 RGB 滤光比例，不同比例混合 → 不同颜色。

## 十九、常见问题

| 问题 | 解答 |
|------|------|
| MCU 模式和 RGB 模式的核心区别？ | **GRAM 的位置**不同：MCU 在液晶内部，RGB 在主机侧 |
| 嵌入式单片机用哪种模式？ | **MCU 模式**，资源需求少，可用 FSMC 控制 |
| 电脑显示器用哪种模式？ | **RGB 模式**，需要显卡输出数据流 |
| 为什么 MCU 模式显示较慢？ | 液晶驱动器处理能力有限，每帧需要通过接口传输数据 |
| GRAM 是什么？ | 显存，存储所有像素颜色数据的存储矩阵 |
| 光学三原色全混合是什么？ | **白色**（加法混合） |
| 美术三原色全混合是什么？ | **黑色**（减法混合，所有光被吸收） |
| FSMC 怎么控制 LCD？ | LCD 的 GRAM 视为 SRAM 类型，通过不同地址区分命令和数据 |
| RGB565 格式占多少位？ | **16 位**（5 红 + 6 绿 + 5 蓝） |
| 独立显卡为什么贵？ | 高性能 GPU 芯片 + 大容量高速显存 |
| 为什么叫减法三原色？ | 颜料越多 → 吸收的光越多 → 越暗 → 最终黑色 |
| TFT 是什么？ | **薄膜晶体管**（Thin Film Transistor），驱动每个像素点 |
| 分辨率 320×480 表示什么？ | 横向 **320** 像素，纵向 **480** 像素 |
| GRAM 在哪里？ | 集成在 **ILI9486 控制器**内部 |
| 8080 总线标准是什么？ | Intel 提出的并行总线标准，MCU 模式的底层协议 |
| 为什么用 FSMC 控制 LCD？ | 8080 总线标准 ≈ FSMC 扩展存储器方式，可直接复用 |
| RS 信号有什么用？ | 连接 A10，RS=0 传命令，RS=1 传数据 |
| RGB565 中绿色为什么多一位？ | **人眼对绿色最敏感**，多一位可提供更细腻的绿色层次 |
| RGB565 能表示多少种颜色？ | **65536** 种（32×64×32） |
| 纯红色的 RGB565 值？ | **0xF800** |
| ILI9486 支持哪些接口？ | 并行 8080、RGB、SPI、MIPI DSI、MDDI |
| Source 和 Gate 是什么？ | 晶体管的**源极**和**栅极**，驱动像素点矩阵 |
| 960 个 Source 怎么来的？ | 320 列 × 3（每像素 RGB 三个子像素）= 960 |
| 怎么往 LCD 写一个像素的颜色？ | 先发写 GRAM 命令，再发 RGB565 颜色数据 |
| A10 为什么不是地址线功能？ | 连接到 LCD 的 **RS 引脚**，用于区分命令和数据 |
| LCD 有地址线吗？ | **没有**，只有 D[15:0] 数据线，地址通过命令传输 |
| RST 接哪个引脚？ | **PG15**（通用推挽输出） |
| 背光控制接哪个引脚？ | **PB0**（通用推挽输出），信号名 LCD_BG |
| 为什么用 NE4 不用 NE3？ | NE3 已用于 SRAM 扩展，LCD 用 **NE4** 避免地址冲突 |
| LCD 的地址线只有一根够吗？ | 够了，因为地址通过**命令**传输，不需要独立地址线 |
| FSMC 需要配复用模式吗？ | **不需要**，命令/数据区分通过 RS 实现，非真正的地址复用 |
| CCFL 和 LED 背光的区别？ | CCFL 是荧光管（已淘汰），LED 是发光二极管（当前主流） |
| 触摸屏引脚需要配吗？ | **不需要**，当前未连接触摸屏功能 |
