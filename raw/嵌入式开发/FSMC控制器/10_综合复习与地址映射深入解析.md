# 第六章 FSMC 控制器 — 综合复习与地址映射深入解析 笔记

---

## 一、FSMC 功能回顾

### 1.1 FSMC 的定位

```
FSMC（灵活的静态存储器控制器）的核心角色：

  CPU / DMA  ←→  AHB 总线  ←→  FSMC  ←→  外部存储器
                          （中间代理人）

FSMC 的本质：
  → 一个"中间商/代理人"
  → 接收 AHB 总线上的地址、数据、控制信号
  → 根据外部存储器类型转换为对应的通信协议
  → 通过地址线、数据线、控制信号驱动外部存储器

对 CPU 的效果：
  → CPU 访问外部存储器 = 访问片内内存
  → 只需给地址和数据，无需关心底层通信协议
```

### 1.2 之前的方式 vs FSMC 的方式

```
之前扩展外部存储器（I²C / SPI）：
  CPU → 通信模块（I²C/SPI）→ 串并转换 → 外部存储器
  → 需要手动编写通信协议
  → 需要编写接口函数（interface）
  → 串行传输，速度慢
  → 每种存储器需要单独的驱动

FSMC 扩展外部存储器：
  CPU → AHB 总线 → FSMC → 并行地址线/数据线/控制线 → 外部存储器
  → FSMC 自动处理通信协议
  → 并行传输，速度快
  → 配置寄存器即可，无需手动编写协议
  → 统一管理不同类型的存储器
```

### 1.3 FSMC 支持的存储器类型

```
静态存储器（FSMC 支持）：
  ✅ SRAM
  ✅ PSRAM（伪静态 RAM，接口同 SRAM）
  ✅ NOR Flash
  ✅ NAND Flash
  ✅ PC Card

动态存储器（FSMC 不支持）：
  ❌ DRAM
  ❌ SDRAM
  ❌ DDR / DDR2 / DDR3 / DDR4
```

## 二、FSMC 引出的信号线

### 2.1 三类信号线

```
FSMC 通过 GPIO 复用引出的信号线分为三类：

① 地址信号线 A[25:0]
   → 共 26 根
   → 传输存储单元的地址

② 数据信号线 D[15:0]
   → 共 16 根
   → 并行传输数据

③ 控制信号线
   → NE[4:1]：片选信号
   → NOE：读使能
   → NWE：写使能
   → NBL[1:0]：高/低字节使能
   → NADV：地址有效信号（复用模式）
   → NWAIT：等待信号
   → CLK：同步时钟（同步模式）
```

### 2.2 引脚数量的实际使用

```
FSMC 理论引出：
  → 26 根地址线（A[25:0]）
  → 16 根数据线（D[15:0]）
  → 若干控制信号线

实际连接 IS62WV51216：
  → 19 根地址线（A[18:0]）→ 芯片只有 19 个地址引脚
  → 16 根数据线 → 全部使用
  → 控制信号 → CS/OE/WE/UB/LB

未使用的地址线：
  → A[25:19] 未连接（IS62WV51216 不需要）
  → 在 16 位模式下，A[0] 也可能不直接连接到芯片
```

## 三、32 位地址的逐级解析

### 3.1 从 32 位到 26 位

```
AHB 总线地址线：32 位（HADDR[31:0]）
FSMC 输出地址线：26 位（A[25:0]）

对应关系：
  → 取 HADDR 的低 26 位
  → 高 6 位用于选择存储器区域（Block/Bank/子区）
  → 低 26 位作为 FSMC 的地址输出

示例：地址 0x6800_0001
  → 二进制：0110 1000 0000 0000 0000 0000 0000 0001
  → 高 6 位：011010 → 确定存储区域
  → 低 26 位：00_0000_0000_0000_0000_0000_0001 → FSMC 输出
```

### 3.2 高 6 位的含义

```
32 位地址的前 6 位用于逐级选择存储区域：

  位 [31:29] → Block 号（3 位，选择 8 个 Block 之一）
  位 [28]    → Bank 号（1 位，选择 Block 内的 Bank）
  位 [27:26] → 子区号（2 位，选择 Bank 内的 4 个子区）

示例：0x6800_0001

  位 [31:29] = 011 → Block 3（FSMC 扩展存储器）
  位 [28]    = 0   → Bank 1（NOR Flash / SRAM）
  位 [27:26] = 10  → 子区 3（NE3 片选）
  
  确认：0x6800_0000 ~ 0x6BFF_FFFF → Bank1-3（NE3）✅
```

### 3.3 逐级选择过程

```
第一步：选择 Block（3 位）

  Block 号    前 3 位    地址范围
  ─────────────────────────────────────
  Block 0     000       0x0000_0000 ~ 0x1FFF_FFFF
  Block 1     001       0x2000_0000 ~ 0x3FFF_FFFF
  Block 2     010       0x4000_0000 ~ 0x5FFF_FFFF
  Block 3     011       0x6000_0000 ~ 0x7FFF_FFFF  ← FSMC
  Block 4     100       0x8000_0000 ~ 0x9FFF_FFFF
  Block 5     101       0xA000_0000 ~ 0xBFFF_FFFF
  Block 6     110       0xC000_0000 ~ 0xDFFF_FFFF
  Block 7     111       0xE000_0000 ~ 0xFFFF_FFFF

  0x6 = 0110 → 前 3 位 = 011 → Block 3 ✅

第二步：选择 Bank（1 位）

  Block 3 内：
    位 [28] = 0 → Bank 1（NOR Flash / SRAM）→ 0x6xxx
    位 [28] = 1 → Bank 2（NAND Flash）→ 0x7xxx

  0x68 = 0110_1000 → 位 [28] = 0 → Bank 1 ✅

第三步：选择子区（2 位）

  Bank 1 内：
    位 [27:26] = 00 → 子区 1（NE1）→ 0x60xx
    位 [27:26] = 01 → 子区 2（NE2）→ 0x64xx
    位 [27:26] = 10 → 子区 3（NE3）→ 0x68xx  ← 我们用这个
    位 [27:26] = 11 → 子区 4（NE4）→ 0x6Cxx

  0x68 = 0110_1000 → 位 [27:26] = 10 → 子区 3（NE3）✅
```

### 3.4 低 26 位的含义

```
前 6 位已经确定了存储区域（子区 3，地址范围 0x6800_0000 ~ 0x6BFF_FFFF）

低 26 位 = FSMC 输出的地址线 A[25:0]
  → 用于在该子区内选择具体的存储单元
  → 2^26 = 64M 个地址 → 与子区大小 64 MB 吻合

示例：0x6800_0001
  → 低 26 位 = 0x00_0001
  → 选择子区 3 内的第 1 个存储单元
```

## 四、8 位 vs 16 位数据宽度的地址对齐

### 4.1 核心问题

```
CPU 按字节编址：每个地址对应 1 字节
IS62WV51216 按 16 位编址：每个地址对应 2 字节

冲突：
  → CPU 地址 0x0000 → 第 1 个字节
  → CPU 地址 0x0001 → 第 2 个字节
  → 但 SRAM 地址 0x0000 → 第 1 个 16 位单元（字节 0 和字节 1）
  → SRAM 地址 0x0001 → 第 2 个 16 位单元（字节 2 和字节 3）

  → 如果直连，CPU 地址 0x0001 会选中 SRAM 的第 2 个单元
  → 但实际上 CPU 想访问的是第 1 个单元的高/低字节
  → 地址对应关系错误！
```

### 4.2 8 位数据宽度（直连模式）

```
外部存储器为 8 位时：
  → FSMC 地址线与 AHB 地址线直连
  → FSMC_A[N] = HADDR[N]
  → 一个地址 = 1 字节 → 完全对应

  HADDR[25:0]  ←→  FSMC_A[25:0]（一一对应）

示例：
  CPU 给出地址 0x0001 → HADDR[0] = 1
  → FSMC_A[0] = 1 → 选择存储单元 1
  → 读取 1 字节数据
  → 完全正确 ✅
```

### 4.3 16 位数据宽度（交叉连接模式）

```
外部存储器为 16 位时：
  → FSMC 地址线与 AHB 地址线错位连接
  → FSMC_A[N] = HADDR[N+1]
  → HADDR[0] 不使用（16 位对齐）
  → 一个 FSMC 地址 = 2 字节

  HADDR[25:1]  ←→  FSMC_A[24:0]（错开 1 位）
  HADDR[0]     →   不连接（由 NBL 掩码替代）

交叉连接示意：
  HADDR[1]  →  FSMC_A0
  HADDR[2]  →  FSMC_A1
  HADDR[3]  →  FSMC_A2
  ...
  HADDR[24] →  FSMC_A23
  HADDR[25] →  FSMC_A24
  HADDR[0]  →  （丢弃，由 NBL 控制高/低字节）
```

### 4.4 16 位模式的地址解析示例

```
CPU 给出地址 0x6800_0000：

  忽略前 6 位（选择区域），看低 26 位：
  HADDR[25:0] = 0x000_0000

  交叉连接后 FSMC 输出：
  FSMC_A[24:0] = HADDR[25:1] = 0x000_0000
  → SRAM 地址 = 0 → 选择第 0 个 16 位单元
  → 读/写该单元的 16 位数据（UB=0, LB=0 → 全 16 位）

CPU 给出地址 0x6800_0001：

  低 26 位：
  HADDR[25:0] = 0x000_0001

  交叉连接后 FSMC 输出：
  FSMC_A[24:0] = HADDR[25:1] = 0x000_0000（右移 1 位，HADDR[0] 丢弃）
  → SRAM 地址 = 0 → 选择第 0 个 16 位单元
  → 但此时 HADDR[0] = 1 → 由 NBL 控制只访问高字节或低字节
  → UB=0, LB=1 或 UB=1, LB=0（取决于具体实现）

CPU 给出地址 0x6800_0002：

  低 26 位：
  HADDR[25:0] = 0x000_0002

  交叉连接后 FSMC 输出：
  FSMC_A[24:0] = HADDR[25:1] = 0x000_0001
  → SRAM 地址 = 1 → 选择第 1 个 16 位单元
  → 读/写该单元的 16 位数据（UB=0, LB=0 → 全 16 位）
```

### 4.5 错位连接的本质

```
为什么 16 位模式要错位？

  本质原因：
    CPU 编址单位 = 1 字节
    SRAM 编址单位 = 2 字节

    → CPU 地址 0 和 1 都在 SRAM 的第 0 个单元内
    → CPU 地址 2 和 3 都在 SRAM 的第 1 个单元内
    → 以此类推...

    → SRAM 的地址 = CPU 地址 ÷ 2 = CPU 地址右移 1 位
    → 这就是错位 1 位的数学本质

    → CPU 地址的最低位（HADDR[0]）用来区分同一 16 位单元内的高/低字节
    → 由 NBL 信号控制（UB/LB 掩码）

  图示：
    CPU 地址：  0    1    2    3    4    5    6    7
    字节编号：  B0   B1   B2   B3   B4   B5   B6   B7
    SRAM 单元： |--单元0--| |--单元1--| |--单元2--| |--单元3--|
    SRAM 地址：   0         1         2         3
    NBL 控制：  L  H      L  H      L  H      L  H

    → HADDR[0] = 0 → 低字节（LB 使能）
    → HADDR[0] = 1 → 高字节（UB 使能）
    → FSMC_A[N] = HADDR[N+1] → SRAM 地址
```

## 五、BCR 配置寄存器详解

### 5.1 BCR3 关键配置位

```
BCR3（Bank1-3 配置寄存器）= BTCR[4]

位       名称        配置值    说明
──────────────────────────────────────────────
Bit 0    MBKEN       1         存储器块使能
Bit 1    MUXEN       0         禁用地址/数据复用
Bit 3:2  MTYP[1:0]   00        SRAM/ROM 类型
Bit 5:4  MWID[1:0]   01        16 位数据宽度
Bit 6    FACCEN      0         禁止 Flash 访问
Bit 12   WREN        1         允许写入
Bit 14   EXTMOD      0         模式 1（不使用扩展模式）

BCR3 配置值 = 0x1011
```

### 5.2 各配置位的底层原理

```
① MBKEN = 1（存储器块使能）
   → 打开 Bank1-3 的使能
   → 默认只有 Bank1 使能，其余需要手动开启

② MUXEN = 0（禁用复用）
   → 独立的地址线和数据线
   → 不共用引脚
   → 注意：复位后默认为 1（复用模式），必须显式配置为 0

③ MTYP = 00（SRAM/ROM 类型）
   → 决定地址的前 6 位选择的存储区域类型
   → 00 = SRAM/ROM → Bank 1
   → 01 = PSRAM
   → 10 = NOR Flash
   → 注意：Bank1 复位后默认为 NOR Flash，需改为 SRAM

④ MWID = 01（16 位数据宽度）
   → 决定 AHB 地址线与 FSMC 输出地址线的连接关系
   → 00 = 8 位：直连（FSMC_A[N] = HADDR[N]）
   → 01 = 16 位：错位（FSMC_A[N] = HADDR[N+1]）
   → 复位后默认就是 01（16 位）

⑤ FACCEN = 0（禁止 Flash 访问）
   → SRAM 不需要 Flash 访问功能
   → 直接禁止

⑥ WREN = 1（写使能）
   → 允许写入操作
   → 复位后默认就是 1

⑦ EXTMOD = 0（模式 1）
   → 不使用扩展模式
   → 读写时序共用 BTR3 寄存器
   → 不需要 BWTR3
```

### 5.3 必须显式配置 vs 可用默认值

```
必须显式配置（复位值不对或不确定）：
  ① MBKEN = 1（使能）
  ② MUXEN = 0（默认为 1，必须改为 0）
  ③ MTYP = 00（默认为 NOR Flash，必须改为 SRAM）
  ④ FACCEN = 0（禁止 Flash 访问）

可使用默认值（复位值已正确）：
  ⑤ MWID = 01（默认就是 16 位）
  ⑥ WREN = 1（默认允许写入）
  ⑦ EXTMOD = 0（默认不使用扩展模式）

建议：全部显式配置，代码更清晰
```

## 六、BTR 时序寄存器详解

### 6.1 BTR3 关键配置位

```
BTR3（Bank1-3 时序寄存器）= BTCR[5]

位        名称        配置值    说明
──────────────────────────────────────────────
Bit 3:0   ADDSET      0x0       地址建立时间（最小值）
Bit 7:4   ADDHLD      0x0       地址保持时间（模式 1 不用）
Bit 15:8  DATASET     0x02      数据建立时间（≥ 40 ns）
Bit 19:16 BUSTURN     0x0       总线转换周期（不用）
Bit 23:20 CLKDIV      0x0       时钟分频（异步不用）
Bit 27:24 DATLAT      0x0       数据延迟（异步不用）
Bit 29:28 ACCMOD      0x0       访问模式（模式 1 不用）

BTR3 配置值 = 0x00000200
```

### 6.2 核心参数计算

```
HCLK = 72 MHz → 1 个时钟周期 ≈ 13.9 ns

① ADDSET（地址建立时间）
   → 芯片要求：tSA ≥ 0 ns（无下限）
   → ADDSET = 0 → 实际 = 1 × 13.9 ns ≈ 13.9 ns
   → 满足要求 ✅

② DATASET（数据建立时间）
   → 芯片要求：tPWE ≥ 40 ns（WE 有效宽度）
   → DATASET + 1 个周期 ≥ 40 ns
   → DATASET ≥ 40 / 13.9 - 1 ≈ 1.88
   → DATASET ≥ 2 → 取 2（最小满足）

实际测试结果：
  DATASET = 0  → ❌ 失败（数据写入不正确）
  DATASET = 1  → ✅ 勉强可以（不太稳定）
  DATASET = 2  → ✅ 正常工作（满足 40 ns 要求）
  DATASET = 3  → ✅ 正常工作（有余量）
  DATASET = 71 → ✅ 正常工作（1 μs，非常保守）
```

### 6.3 时序配置与芯片参数的对应

```
IS62WV51216 参数         FSMC 配置         对应关系
─────────────────────────────────────────────────────────
tSA（地址建立）≥ 0 ns    ADDSET = 0        1 × 13.9 ns ≥ 0 ns ✅
tPWE（WE 宽度）≥ 40 ns   DATASET = 2       3 × 13.9 ns ≈ 41.7 ns ≥ 40 ns ✅
tRC（读周期）= 55 ns      总时间            (0+1)+(2+1)+1 = 4 × 13.9 ≈ 55.6 ns ✅
tWC（写周期）= 55 ns      总时间            (0+1)+(2+1)+1 = 4 × 13.9 ≈ 55.6 ns ✅
```

## 七、模式 1 时序分析

### 7.1 模式 1 读时序

```
模式 1 读时序特点：
  → NOE 始终保持低电平有效
  → 不需要等地址建立后再拉低 NOE
  → 比模式 A 更简单

时序流程：
  ① NE 拉低（片选有效）
  ② 地址线输出有效地址
  ③ NOE 保持低电平（始终有效）
  ④ 等待 AddSet + 1 个周期（地址建立）
  ⑤ 等待 DataSet + 1 个周期（等待数据输出）
  ⑥ 采样数据总线，读取数据
  ⑦ 数据保持 1 个周期
  ⑧ NOE 恢复高电平，NE 恢复高电平

读操作总时间 = AddSet + DataSet + 3 个周期
```

### 7.2 模式 1 写时序

```
模式 1 写时序特点：
  → NWE 在地址建立后拉低
  → 数据由 FSMC 驱动到数据总线
  → WE 有效宽度 = DataSet + 1 个周期

时序流程：
  ① NE 拉低（片选有效）
  ② 地址线输出有效地址
  ③ 等待 AddSet + 1 个周期（地址建立）
  ④ NWE 拉低（写使能有效）
  ⑤ FSMC 驱动数据到数据总线
  ⑥ 保持 DataSet + 1 个周期（数据建立）
  ⑦ NWE 恢复高电平
  ⑧ 数据保持 1 个周期
  ⑨ NE 恢复高电平

写操作总时间 = AddSet + DataSet + 3 个周期
```

## 八、模式选择

### 8.1 六种模式对比

```
模式      说明                寄存器配置
────────────────────────────────────────────────────
模式 1    最简单，读写合一      BTR（读写共用）
模式 A    扩展，读写分离        BTR（读）+ BWTR（写）
模式 B    扩展                 BTR + BWTR
模式 C    扩展                 BTR + BWTR
模式 D    扩展                 BTR + BWTR
复用模式  地址数据复用          BTR + BWTR

选择依据：
  → SRAM 读写速度基本相同 → 模式 1 足够
  → 如需读写分别优化 → 使用模式 A
  → 我们使用模式 1 → BCR.EXTMOD = 0 → 只用 BTR
```

### 8.2 ACCMOD 配置

```
BTR.ACCMOD（访问模式）：
  → 仅当 BCR.EXTMOD = 1（开启扩展模式）时有效
  → 00 = 模式 A
  → 01 = 模式 B
  → 10 = 模式 C
  → 11 = 模式 D

  → BCR.EXTMOD = 0（模式 1）→ ACCMOD 不起作用
  → 配置为 00 即可
```

## 九、完整配置代码

### 9.1 BCR3 + BTR3 配置

```c
/* BCR3 配置（BTCR[4]）*/
FSMC_Bank1->BTCR[4] = 0;                    /* 先清零 */
FSMC_Bank1->BTCR[4] |= (1 << 0);            /* MBKEN = 1：使能存储器块 */
FSMC_Bank1->BTCR[4] &= ~(1 << 1);           /* MUXEN = 0：不使用复用 */
FSMC_Bank1->BTCR[4] &= ~(3 << 2);           /* MTYP = 00：SRAM/ROM */
FSMC_Bank1->BTCR[4] |= (1 << 4);            /* MWID = 01：16 位 */
FSMC_Bank1->BTCR[4] &= ~(1 << 6);           /* FACCEN = 0：禁止 Flash */
FSMC_Bank1->BTCR[4] |= (1 << 12);           /* WREN = 1：允许写入 */
FSMC_Bank1->BTCR[4] &= ~(1 << 14);          /* EXTMOD = 0：模式 1 */

/* BTR3 配置（BTCR[5]）*/
FSMC_Bank1->BTCR[5] = 0;                    /* 先清零 */
FSMC_Bank1->BTCR[5] |= (0 << 0);            /* ADDSET = 0：最小值 */
FSMC_Bank1->BTCR[5] |= (2 << 8);            /* DATASET = 2：≥ 40 ns */
```

### 9.2 配置值速查

```
BCR3 = 0x0000_1011

  二进制：0000 0000 0000 0000 0001 0000 0001 0001
  Bit 0    = 1（MBKEN）
  Bit 1    = 0（MUXEN）
  Bit 3:2  = 00（MTYP = SRAM/ROM）
  Bit 5:4  = 01（MWID = 16 位）
  Bit 6    = 0（FACCEN）
  Bit 12   = 1（WREN）
  Bit 14   = 0（EXTMOD）

BTR3 = 0x0000_0200

  二进制：0000 0000 0000 0000 0000 0010 0000 0000
  Bit 3:0   = 0000（ADDSET = 0）
  Bit 7:4   = 0000（ADDHLD = 0）
  Bit 15:8  = 00000010（DATASET = 2）
  其余位    = 0
```

## 十、DATASET 实测结果

```
DATASET 值    实际 WE 时间        测试结果
───────────────────────────────────────────
    0         1 × 13.9 = 13.9 ns   ❌ 失败
    1         2 × 13.9 = 27.8 ns   ⚠️ 勉强（不稳定）
    2         3 × 13.9 = 41.7 ns   ✅ 正常
    3         4 × 13.9 = 55.6 ns   ✅ 正常
   71         72 × 13.9 = 1000 ns  ✅ 非常稳定

结论：
  → DATASET = 2 是理论最小值（满足 40 ns 要求）
  → 实测 DATASET = 2 可以正常工作
  → DATASET = 1 有时可以，但不够稳定
  → DATASET = 0 完全不行
  → 保险起见建议 DATASET = 2 或更大

注意：
  → 硬件时序可能受环境影响（温度、电源波动等）
  → 建议留一定余量，不要用极限值
  → DATASET = 2 或 3 是比较好的选择
```

## 十一、关键概念速查

| 概念 | 说明 |
|------|------|
| FSMC | 灵活的静态存储器控制器，"中间代理人" |
| AHB 地址 32 位 | HADDR[31:0]，CPU 发出的地址 |
| FSMC 输出 26 位 | A[25:0]，FSMC 输出到外部存储器的地址线 |

| 低 26 位 | 子区内的存储单元地址（64M 个地址） |
| 8 位直连 | FSMC_A[N] = HADDR[N]，一一对应 |
| 16 位交叉 | FSMC_A[N] = HADDR[N+1]，错开 1 位 |
| HADDR[0] | 16 位模式下丢弃，由 NBL 控制高/低字节 |
| NE3 | 子区 3 片选，对应 0x6800_0000 ~ 0x6BFF_FFFF |
| BCR | 总线配置寄存器，配置存储器类型/宽度/模式 |
| BTR | 总线时序寄存器，配置 AddSet/Dataset |
| BWTR | 总线写时序寄存器，扩展模式使用 |
| BTCR[4] | = BCR3（Bank1-3 配置） |
| BTCR[5] | = BTR3（Bank1-3 时序） |
| MBKEN | 存储器块使能，置 1 开启 |
| MUXEN | 地址/数据复用使能，模式 1 设为 0 |
| MTYP | 存储器类型：00=SRAM/ROM, 01=PSRAM, 10=NOR Flash |
| MWID | 数据宽度：00=8 位, 01=16 位 |
| FACCEN | Flash 访问使能，SRAM 设为 0 |
| EXTMOD | 扩展模式使能，模式 1 设为 0 |
| ADDSET | 地址建立时间，值 +1 为实际周期数 |
| DATASET | 数据建立时间，值 +1 为实际周期数 |
| BCR3 = 0x1011 | 配置值 |
| BTR3 = 0x00000200 | 配置值（ADDSET=0, DATASET=2） |
| HCLK = 72 MHz | 时钟周期 ≈ 13.9 ns |

## 十二、常见问题

| 问题 | 解答 |
|------|------|
| 32 位地址的高 6 位干什么用了？ | 选择 Block（3 位）+ Bank（1 位）+ 子区（2 位） |
| 为什么 FSMC 只输出 26 位？ | 高 6 位已用于选择存储区域，低 26 位用于区内寻址 |
| 16 位模式为什么要错位？ | CPU 按字节编址，SRAM 按 16 位编址，错位 1 位 = 地址 ÷ 2 |
| HADDR[0] 丢了怎么办？ | 由 NBL 信号控制高/低字节选择（UB/LB） |
| MTYP 默认是什么？ | Bank1 默认为 NOR Flash（10），**必须改为** SRAM（00） |
| MUXEN 默认是什么？ | 默认为 1（复用模式），**必须改为** 0 |
| DATASET 至少配多少？ | **≥ 2**（实测 2 可工作，1 不稳定，0 失败） |
| ADDSET 配多少？ | **0**（芯片无下限要求） |
| 模式 1 和模式 A 区别？ | 模式 1 读写合一（BTR），模式 A 读写分离（BTR + BWTR） |
| 为什么不用扩展模式？ | SRAM 读写速度相同，模式 1 足够简单高效 |
| DATASET 配大一点有坏处吗？ | 没有功能性影响，只是速度稍慢，但更稳定 |
| FSMC 相比 SPI 有什么优势？ | **并行传输**速度快，**自动管理**协议，CPU 负担轻 |
