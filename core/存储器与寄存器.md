## 一、存储器概述

存储器是用于存储信息的计算机部件，是现代计算机结构的核心组成部分。

### 1.1 存储器的本质与作用

存储器在冯·诺依曼体系结构中的核心作用：
- **存储程序和数据**：计算机将需要的数据保存下来，后续需要时可随时读取使用
- **执行程序，进行控制**：计算机按照存储的指令顺序逐条执行任务

存储器中存放的信息本质是一串 0 和 1 的二进制序列，可以是要执行的代码/指令，也可以是具体要用到的数据。

📄 [原文01: 存储器概述](../raw/嵌入式开发/存储器与寄存器/01_存储器概述.md)

### 1.2 存储器分类总览

存储器按存储特性分为两大类：

| 类型 | 全称 | 核心特性 | 掉电表现 | 典型应用 |
|------|------|----------|----------|----------|
| **RAM** | Random Access Memory（随机存取存储器） | 易失性 | 掉电数据丢失 | 运行时变量、数据缓存 |
| **ROM** | Read Only Memory（只读存储器） | 非易失性 | 掉电数据不丢失 | 程序代码、固件、配置数据 |

**为什么现在用"易失性"而非"可读写"来区分？**
- 早期：ROM 确实只能读不能写，RAM 可读可写
- 现在：随着技术发展，ROM 也变得可读可写了（如 EEPROM、Flash）
- 因此现在以"易失性"（掉电是否丢数据）作为核心区分依据

📄 [原文01: 存储器概述](../raw/嵌入式开发/存储器与寄存器/01_存储器概述.md)

### 1.3 按存储介质划分

| 介质类型 | 存储方式 | 代表设备 | 速度 | 成本 | 趋势 |
|---------|---------|---------|------|------|------|
| 半导体 | 电信号 | Flash、RAM | 快 | 较高 | **主流方向** |
| 磁介质 | 磁信号 | 机械硬盘、磁带 | 慢 | 低 | 逐步淘汰 |
| 光介质 | 光信号 | CD/DVD/BD | 中 | 低 | 仍有部分场景 |

📄 [原文01: 存储器概述](../raw/嵌入式开发/存储器与寄存器/01_存储器概述.md)

## 二、RAM 详解

### 2.1 RAM 基本概念

RAM（Random Access Memory，随机存取存储器）的核心特点：
- **可读可写**：既能存又能取
- **随机访问**：给任意地址，直接读写（"随机"是"任意"的意思，不是"随机"的"随机"）
- **易失性**：掉电数据丢失

### 2.2 RAM 分类：SRAM 与 DRAM

| 特性 | SRAM（静态RAM） | DRAM（动态RAM） |
|------|----------------|----------------|
| 存储单元 | 6晶体管触发器（6T结构） | 1晶体管+1电容（1T1C结构） |
| 刷新 | **不需要**刷新操作 | **需要**定期刷新 |
| 速度 | **快**（触发器直接翻转） | 相对**较慢**（电容充放电需要时间） |
| 成本 | **高**（每个单元6个晶体管） | **低**（结构简单） |
| 集成度 | **低**（结构复杂，芯片面积大） | **高**（单位面积容量大） |
| 容量 | **小**（单颗芯片容量有限） | **大**（单颗芯片容量可达数GB） |
| 典型用途 | CPU高速缓存（Cache） | 电脑内存条（DDR4/DDR5） |

**设计取舍思想**：
- 追求速度（SRAM）：结构复杂 → 成本高 → 集成度低 → 容量小
- 追求容量（DRAM）：结构简单 → 成本低 → 集成度高 → 速度慢
- 实际应用：两者配合，CPU ← SRAM（Cache）← DRAM（内存），兼顾速度和容量

📄 [原文02: RAM与ROM详解](../raw/嵌入式开发/存储器与寄存器/02_RAM与ROM详解.md)

### 2.3 DRAM 为什么需要刷新

DRAM 利用电容的充放电特性存储数据：
- 电容充电（有电荷）→ 表示 1
- 电容放电（无电荷）→ 表示 0

**电容的物理特性带来的问题**：
1. **自然放电**：即使不读写，电容中的电荷也会缓慢泄漏，存储的 1 会慢慢变成 0
2. **电荷吸收**：相邻电路可能干扰，存储的 0 可能慢慢变成 1

**解决方法**：定期刷新
- 读取每个单元的电容电量
- 电量 > 满电量的 1/2 → 判定为 1 → 重新充满电
- 电量 < 满电量的 1/2 → 判定为 0 → 放电清零
- 重新写回正确的值，保证数据不丢失

📄 [原文02: RAM与ROM详解](../raw/嵌入式开发/存储器与寄存器/02_RAM与ROM详解.md)

### 2.4 单片机 vs 个人电脑的内存结构

| 对比项 | STM32 单片机 | 个人电脑（PC） |
|--------|-------------|----------------|
| RAM 类型 | 直接使用 SRAM | 使用 DRAM（DDR4/DDR5） |
| 容量 | 小（如 20KB） | 大（8GB/16GB/32GB） |
| 缓存 | 不需要（SRAM 速度够快） | CPU 内部有多级 Cache（L1/L2/L3） |
| 结构 | 简单，无需额外缓存层 | CPU ← L1/L2/L3 Cache ← 内存(DRAM) |

📄 [原文02: RAM与ROM详解](../raw/嵌入式开发/存储器与寄存器/02_RAM与ROM详解.md)

## 三、ROM 详解

### 3.1 ROM 基本概念

ROM（Read Only Memory，只读存储器）的核心特点：
- **非易失性**：掉电数据不丢失
- **适合长期存储**：程序代码、固件、配置数据

**名称由来**：早期这类存储器真的只能读、不能写，数据出厂时就固化在芯片中，用户无法修改。

### 3.2 ROM 的发展路线

| 类型 | 全称 | 写入方式 | 擦除方式 | 可重复擦写 | 典型芯片 |
|------|------|---------|---------|:----------:|---------|
| **Mask ROM** | 掩膜 ROM | 工厂掩膜固化 | 不可擦除 | ❌ | 早期游戏卡带 |
| **PROM** | 可编程 ROM | 用户一次性编程 | 不可擦除 | ❌ | 熔丝式存储器 |
| **EPROM** | 可擦除可编程 ROM | 用户编程 | **紫外线**照射整片擦除 | ✅（整片） | 带石英窗芯片 |
| **EEPROM** | 电可擦除可编程 ROM | 用户编程 | **电信号**按字节擦除 | ✅（按字节） | AT24C02 |
| **Flash** | 闪存 | 用户编程 | **电信号**按块/扇区擦除 | ✅（按块） | W25Q32、SSD |

**识别 EPROM**：芯片上有一个小圆窗/小方窗（石英窗口）→ 就是 EPROM

📄 [原文02: RAM与ROM详解](../raw/嵌入式开发/存储器与寄存器/02_RAM与ROM详解.md)

### 3.3 Flash（闪存）

Flash 是当前最主流的 ROM 类型，在 EEPROM 技术基础上发展而来。

**相比 EEPROM 的优势**：
- 容量更大（可达数 MB 甚至数 GB）
- 读取速度更快
- 成本更低
- 擦写方式优化（按块/扇区擦除，而非按字节）

**Flash 的分类**：
- **NOR Flash**：可按字节读取，适合存储代码（可直接执行），如 W25Q32
- **NAND Flash**：按页/块读写，容量更大、成本更低，适合存储大量数据，如 U 盘、SSD、手机存储

**当前应用**：
- U 盘、固态硬盘（SSD）的存储介质 → Flash
- 手机存储芯片 → Flash（NAND Flash）
- STM32 内部程序存储器 → Flash
- W25Q32 外部存储芯片 → NOR Flash

📄 [原文02: RAM与ROM详解](../raw/嵌入式开发/存储器与寄存器/02_RAM与ROM详解.md)

### 3.4 Flash 还能叫 ROM 吗？

**名称的历史遗留问题**：
- Flash 明显可以读也可以写，为什么还叫 ROM？
- 答案：历史名称的保留

**生活中的类比**：
- 汽车：早期烧汽油 → 叫"汽车"，现在很多是电动汽车，但依然叫"汽车"
- 火车：早期蒸汽机车，烧煤冒火 → 叫"火车"，现在电气化高速列车，但依然叫"火车"
- ROM：早期真的只能读不能写，现在 Flash 可读可写，但依然叫"ROM"

**ROM 与 RAM 的本质区别**（虽然 ROM 现在也能读写了）：

| 对比项 | RAM | ROM（Flash） |
|--------|-----|-------------|
| 写入方式 | 直接改写（触发器翻转/电容充放电） | 需要先擦除再写入 |
| 读写速度 | 读写速度一样快 | 读取快，写入慢 |
| 擦写寿命 | 理论上无限读写 | 有擦写寿命上限（1万~10万次） |
| 易失性 | 掉电数据丢失 | 掉电数据保持 |
| 底层存储原理 | 电子电路状态（触发器/电容） | 浮栅晶体管（电荷捕获） |
| 应用场景 | 运行时数据（变量、栈、堆） | 长期存储（程序代码、固件、数据） |

📄 [原文02: RAM与ROM详解](../raw/嵌入式开发/存储器与寄存器/02_RAM与ROM详解.md)

## 四、STM32 存储器映射

### 4.1 存储器映射的概念

**为什么需要存储器映射**：
- CPU 需要访问各种存储单元（SRAM、Flash、外设寄存器）
- 存储器本身没有地址信息
- 必须为所有存储区域分配统一的地址空间，每个存储单元获得唯一的地址编码

**存储器映射（Memory Map）**：
- 为每一个存储单元分配一个唯一的地址
- 地址本质：无符号整数编码（十六进制表示）
- STM32 地址宽度：32 位，形成芯片理论上的完整地址空间

**注意**：存储器映射不只针对 SRAM 和 Flash，所有片内外设的寄存器也需要映射地址。

📄 [原文03: STM32存储器映射](../raw/嵌入式开发/存储器与寄存器/03_STM32存储器映射.md)

### 4.2 32 位地址空间

32 位地址可表示 2^32 个地址：
- 2^32 = 4 × (2^10 × 2^10 × 2^10) = 4 × 1G = 4 GB
- 地址范围：0x0000_0000 ~ 0xFFFF_FFFF

**32 位与 64 位系统对比**：
- 32 位系统：最大可访问 4 GB 内存（早期电脑/STM32）
- 64 位系统：理论上可访问的内存极其巨大，内存扩展几乎没有上限

📄 [原文03: STM32存储器映射](../raw/嵌入式开发/存储器与寄存器/03_STM32存储器映射.md)

### 4.3 小端存储格式

**问题背景**：一个 32 位数据占 4 个字节，4 个字节有 4 个不同的地址，低位字节存放在低地址还是高地址？

**两种存储格式**：
- **大端存储（Big Endian）**：低位字节存放在高地址，高位字节存放在低地址
- **小端存储（Little Endian）**：低位字节存放在低地址，高位字节存放在高地址 ← STM32 和大多数计算机使用

**为什么使用小端存储**：方便数据类型转换
- uint32_t → uint8_t：直接取首地址对应的那 1 个字节即可
- uint32_t → uint16_t：从首地址取 2 个字节即可
- 核心思想：找到首地址（最低地址），截取需要的字节数，低位数据天然就在首地址处

📄 [原文03: STM32存储器映射](../raw/嵌入式开发/存储器与寄存器/03_STM32存储器映射.md)

### 4.4 STM32 存储器空间划分（八大 Block）

STM32 的 4 GB 地址空间划分为 8 个 Block，每个 Block 大小 512 MB（2^29 字节）：

| Block | 地址范围 | 内容 | 重要程度 |
|:-----:|---------|------|:--------:|
| **0** | 0x0000_0000 ~ 0x1FFF_FFFF | 启动别名 / Flash / System Memory | ⭐⭐⭐ |
| **1** | 0x2000_0000 ~ 0x3FFF_FFFF | SRAM | ⭐⭐⭐ |
| **2** | 0x4000_0000 ~ 0x5FFF_FFFF | 片内外设寄存器 | ⭐⭐⭐ |
| 3 | 0x6000_0000 ~ 0x7FFF_FFFF | FSMC Bank 1 & 2 | ⭐⭐ |
| 4 | 0x8000_0000 ~ 0x9FFF_FFFF | FSMC Bank 3 & 4 | ⭐⭐ |
| 5 | 0xA000_0000 ~ 0xBFFF_FFFF | FSMC 寄存器 | ⭐ |
| 6 | 0xC000_0000 ~ 0xDFFF_FFFF | 保留 | — |
| 7 | 0xE000_0000 ~ 0xFFFF_FFFF | Cortex-M3 内核外设 | ⭐⭐ |

📄 [原文03: STM32存储器映射](../raw/嵌入式开发/存储器与寄存器/03_STM32存储器映射.md)

### 4.5 Block 0 详解 — 启动与 Flash

**Block 0 的地址分布**：
- **启动别名区（Alias）**：0x0000_0000 ~ 0x0000_FFFF，是其他存储区域的"映射窗口"
- **Flash 存储器**：0x0800_0000 ~ 0x0807_FFFF，大小 512 KB，存储程序代码和常量数据
- **System Memory**：0x1FFF_F000 ~ 0x1FFF_F7FF，存储出厂预置的 Bootloader

**启动别名机制**：
STM32 上电后从地址 0x0000_0000 开始执行程序，但 0x0000_0000 本身不直接存储数据，它是其他存储区域的"别名"，具体映射到谁由 BOOT 引脚决定：

| BOOT1 | BOOT0 | 启动方式 | 0x0000_0000 映射到 |
|-------|-------|----------|-------------------|
| x | 0 | 从 Flash 启动 | Flash（0x0800_0000） |
| 0 | 1 | 从 System Memory 启动 | System Memory |
| 1 | 1 | 从 SRAM 启动 | SRAM（0x2000_0000） |

**正常启动流程**：
1. 上电 / 复位
2. 检查 BOOT 引脚状态
3. 确定 0x0000_0000 映射到哪个存储区域
4. CPU 从 0x0000_0000 开始取指令执行
5. 如果映射到 Flash → 执行用户程序
6. 如果映射到 System Memory → 执行 Bootloader

📄 [原文03: STM32存储器映射](../raw/嵌入式开发/存储器与寄存器/03_STM32存储器映射.md)

### 4.6 Block 1 详解 — SRAM

**SRAM 地址空间**：
- 地址范围：0x2000_0000 ~ 0x2000_FFFF
- 大小：64 KB
- 用途：存储运行时变量、栈、堆

**大小计算**：
- 0x2001_0000 - 0x2000_0000 = 0x0001_0000
- 0x1_0000 = 2^16 = 65536 字节 = 64 KB

📄 [原文03: STM32存储器映射](../raw/嵌入式开发/存储器与寄存器/03_STM32存储器映射.md)

### 4.7 Block 2 详解 — 片内外设

Block 2（0x4000_0000 ~ 0x5FFF_FFFF）包含所有片内外设的寄存器地址空间，每个外设模块分配一段连续地址。

**外设基地址示例**：
- GPIOA：0x4001_0800 ~ 0x4001_0BFF
- GPIOB：0x4001_0C00 ~ 0x4001_0FFF
- DMA1：0x4002_0000 ~ 0x4002_03FF
- SPI1：0x4001_3000 ~ 0x4001_33FF
- USART1：0x4001_3800 ~ 0x4001_3BFF

**地址使用方式**：每个外设的寄存器都在其地址范围内，按偏移量排列
- 例：GPIOA 基地址 = 0x4001_0800
  - GPIOA_CRL = 基地址 + 0x00 = 0x4001_0800
  - GPIOA_CRH = 基地址 + 0x04 = 0x4001_0804
  - GPIOA_IDR = 基地址 + 0x08 = 0x4001_0808
  - GPIOA_ODR = 基地址 + 0x0C = 0x4001_080C

📄 [原文03: STM32存储器映射](../raw/嵌入式开发/存储器与寄存器/03_STM32存储器映射.md)

## 五、寄存器详解

### 5.1 寄存器的两个层面理解

**硬件层面**：
- 底层由锁存器 / 触发器构成
- 每一位 = 一个锁存器 / 触发器，可存放一位 0 或 1
- 多个锁存器/触发器组合 → 构成多位寄存器
- 32 位寄存器 = 32 个锁存器/触发器

**软件层面**：
- 本质是一个指针指向的地址空间的别名
- 对应存储器映射中的某一段固定地址
- 通过指针操作该地址来读写寄存器
- 寄存器名称 = 该地址的别名

📄 [原文04: 寄存器详解与地址映射](../raw/嵌入式开发/存储器与寄存器/04_寄存器详解与地址映射.md)

### 5.2 不同类型寄存器的硬件功能

| 寄存器类型 | 全称 | 功能 | 示例 |
|-----------|------|------|------|
| **控制寄存器（CR）** | Control Register | 每一位的输出连接到外设的功能控制电路，写入 0 或 1 → 控制对应功能的开启/关闭 | CR1.MSTR = 1 → 设为主模式 |
| **状态寄存器（SR）** | Status Register | 外部电路的状态信号输入到每一位，读取寄存器 → 获取当前外设的工作状态 | SR.TXE = 1 → 发送缓冲区为空 |
| **数据寄存器（DR）** | Data Register | 纯粹存储一串二进制数据，不直接控制外部电路，也不反映外部状态 | DR = 0x55 → 存储待发送的数据 |

📄 [原文04: 寄存器详解与地址映射](../raw/嵌入式开发/存储器与寄存器/04_寄存器详解与地址映射.md)

### 5.3 寄存器与 SRAM/ROM 的异同

**相同点**：
- 底层存储原理相同：都是用电子器件（锁存器/触发器/电容）存储 0 和 1
- 都需要分配地址才能被 CPU 访问
- 都存在于统一的 4 GB 地址空间中

**不同点**：

| 对比项 | SRAM / ROM | 外设寄存器 |
|--------|-----------|-----------|
| 存储目的 | 存放程序和数据 | 控制外设 / 反映状态 / 传输数据 |
| 容量 | 大（KB ~ MB 级） | 小（每个外设仅十几个 32 位寄存器） |
| 地址分配 | 大块连续区域 | 每个外设一小段连续地址 |
| 访问意义 | 读写数据本身 | 每一位可能有特定的控制/状态含义 |
| 位置 | 独立存储区域 | 分布在各外设模块内部 |

📄 [原文04: 寄存器详解与地址映射](../raw/嵌入式开发/存储器与寄存器/04_寄存器详解与地址映射.md)

### 5.4 寄存器映射

**存储器映射 vs 寄存器映射**：
- **存储器映射（宏观划分）**：把 4 GB 地址空间划分为 8 个 Block，每个 Block 512 MB，粗粒度
- **寄存器映射（细粒度划分）**：在每个外设的地址范围内，为每个具体的寄存器分配精确地址

**寄存器地址的构成**：每个外设寄存器的地址 = 基地址 + 偏移地址

以 GPIOA 为例：
```
外设基地址          = 0x4000_0000（Block 2 起始）
+ APB2 偏移         = 0x0001_0000
──────────────────────────────
APB2 外设基地址      = 0x4001_0000

+ GPIOA 偏移        = 0x0000_0800
──────────────────────────────
GPIOA 基地址        = 0x4001_0800

+ CRL 偏移          = 0x00 → 0x4001_0800
+ CRH 偏移          = 0x04 → 0x4001_0804
+ IDR 偏移          = 0x08 → 0x4001_0808
+ ODR 偏移          = 0x0C → 0x4001_080C
+ BSRR 偏移         = 0x10 → 0x4001_0810
+ BRR 偏移          = 0x14 → 0x4001_0814
+ LCKR 偏移         = 0x18 → 0x4001_0818
```

### 5.5 寄存器在源码中的定义

**定义的整体结构**（三步）：
1. **定义结构体类型**：描述寄存器布局
2. **定义基地址宏**：确定外设的固定地址
3. **定义外设指针宏**：将地址强转为结构体指针

**示例：GPIO 定义**：
```c
/* ① 定义结构体类型 */
typedef struct
{
    __IO uint32_t CRL;      /* 偏移 0x00：端口配置低寄存器 */
    __IO uint32_t CRH;      /* 偏移 0x04：端口配置高寄存器 */
    __IO uint32_t IDR;      /* 偏移 0x08：输入数据寄存器 */
    __IO uint32_t ODR;      /* 偏移 0x0C：输出数据寄存器 */
    __IO uint32_t BSRR;     /* 偏移 0x10：位设置/清除寄存器 */
    __IO uint32_t BRR;      /* 偏移 0x14：位清除寄存器 */
    __IO uint32_t LCKR;     /* 偏移 0x18：锁定寄存器 */
} GPIO_TypeDef;

/* ② 定义基地址宏 */
#define PERIPH_BASE           ((uint32_t)0x40000000)
#define APB2PERIPH_BASE       (PERIPH_BASE + 0x10000)
#define GPIOA_BASE            (APB2PERIPH_BASE + 0x0800)

/* ③ 定义外设指针宏 */
#define GPIOA  ((GPIO_TypeDef *) GPIOA_BASE)
```

**为什么不直接定义结构体变量**：
- 正常做法：GPIO_TypeDef a; → 结构体变量 a 由系统自动分配内存地址（在 SRAM 中随机位置）
- 问题：无法保证地址恰好等于 0x40010800（GPIOA 的真实地址）
- 实际做法：#define GPIOA ((GPIO_TypeDef *) 0x40010800) → 直接将固定地址强转为结构体指针

### 5.6 结构体成员对齐与偏移地址

**为什么成员必须都是 uint32_t**：
- 确保每个成员占 4 字节，偏移量自动匹配硬件寄存器地址
- 如果定义为 uint16_t，结构体对齐后偏移量会错位，访问错误的寄存器

**严丝合缝的对应关系**：

| 硬件寄存器布局 | 结构体成员布局 |
|---------------|---------------|
| 地址 | 偏移 |
| 0x40010800 CRL | 0x00 CRL ← 自动对应 |
| 0x40010804 CRH | 0x04 CRH ← 自动对应 |
| 0x40010808 IDR | 0x08 IDR ← 自动对应 |
| 0x4001080C ODR | 0x0C ODR ← 自动对应 |

### 5.7 寄存器操作的完整链路

以 `GPIOA->ODR |= (1 << 5);`（置 PA5 为高电平）为例：

**完整执行路径**：
1. **GPIOA（宏定义）**：展开为 ((GPIO_TypeDef *) 0x40010800)，得到指向 0x40010800 的结构体指针
2. **GPIOA->ODR（访问结构体成员）**：ODR 偏移量 = 0x0C，实际地址 = 0x40010800 + 0x0C = 0x4001080C
3. **|= (1 << 5)（位操作）**：读取 0x4001080C 处的当前值，将第 5 位置 1，写回 0x4001080C
4. **硬件响应**：ODR 第 5 位对应的锁存器输出高电平，该信号连接到 PA5 引脚的输出驱动电路
5. **引脚输出**：PA5 输出 3.3V 高电平

### 5.8 特殊情况：SPI 寄存器的 RESERVED

SPI 的寄存器是 16 位的（非 32 位），每个寄存器后边都有 RESERVED 用于补齐到 32 位对齐：

```c
typedef struct
{
    __IO uint16_t CR1;      /* 偏移 0x00：控制寄存器 1 */
    uint16_t    RESERVED0;  /* 偏移 0x02：保留（补齐 32 位对齐） */
    __IO uint16_t CR2;      /* 偏移 0x04：控制寄存器 2 */
    uint16_t    RESERVED1;
    // ...
} SPI_TypeDef;
```

**为什么 SPI 需要 RESERVED 而 GPIO 不需要**：
- GPIO 寄存器：每个寄存器都是 32 位（uint32_t），每个恰好占 4 字节 → 与 32 位总线宽度一致，不需要补齐
- SPI 寄存器：每个寄存器只有 16 位（uint16_t），只占 2 字节 → 不够 32 位总线宽度，需要 RESERVED 补齐到 4 字节

## 六、关键概念速查

| 概念 | 说明 |
|------|------|
| RAM | 随机存取存储器，易失性，掉电丢数据，可读可写 |
| SRAM | 静态 RAM，6T 触发器，不需要刷新，快但贵，用于 Cache |
| DRAM | 动态 RAM，1T1C 电容，需要定期刷新，慢但便宜，用于内存 |
| ROM | 只读存储器（历史名称），非易失性，掉电不丢数据 |
| Flash | 闪存，EEPROM 基础上发展，按块擦除，当前主流 ROM |
| EEPROM | 电可擦除可编程 ROM，按字节擦写，如 AT24C02 |
| 存储器映射 | 为每个存储单元分配唯一地址，建立"地址 ↔ 存储单元"对应关系 |
| 小端存储 | 低位字节存放在低地址，STM32 和大多数计算机采用此格式 |
| Block | STM32 将 4 GB 地址空间等分为 8 个 512 MB 的块 |
| 寄存器（硬件） | 由锁存器/触发器构成的存储单元，每位可存 0 或 1 |
| 寄存器（软件） | 指向固定地址的结构体指针的别名 |
| 基地址 | 外设寄存器区域的起始地址 |
| 偏移地址 | 某寄存器相对于基地址的地址偏移量 |
| `__IO` | volatile 关键字，防止编译器优化对寄存器的读写 |

## 七、常见问题

| 问题 | 解答 |
|------|------|
| RAM 和 ROM 最大区别是什么？ | **易失性**：RAM 掉电丢数据，ROM 掉电不丢 |
| SRAM 和 DRAM 最大区别是什么？ | SRAM **不需要刷新**，DRAM **需要定期刷新** |
| 为什么 SRAM 比 DRAM 贵？ | SRAM 每位需 6 个晶体管，DRAM 只需 1 个晶体管 + 1 个电容 |
| Flash 还算 ROM 吗？ | 技术上已可读可写，但名称历史保留，仍称为 ROM |
| Flash 和 RAM 能互相替代吗？ | 不能。Flash 写入慢、有寿命；RAM 掉电丢数据 |
| STM32 为什么直接用 SRAM 做内存？ | 容量小（20KB），SRAM 够用且速度快，无需 DRAM |
| 寄存器底层是什么？ | **锁存器 / 触发器**，每位一个，32 位寄存器 = 32 个 |
| 为什么不用结构体变量而用指针宏？ | 结构体变量由系统分配地址（SRAM 中随机），无法对应到硬件固定地址 |
| GPIOA 的地址怎么算？ | PERIPH_BASE + 0x10000 + 0x0800 = **0x40010800** |
| 存储器映射和寄存器映射的区别？ | 存储器映射是**宏观划分**（Block 级），寄存器映射是**微观划分**（单个寄存器级） |
