
# 第五章 存储器和寄存器 — STM32 存储器映射 笔记

---

## 一、STM32 片内存储器

### 1.1 片内存储器组成

```
STM32 片内存储器主要包含两部分：

① SRAM（静态随机存取存储器）
   → 容量：64 KB
   → 起始地址：0x2000_0000
   → 用途：运行时变量、栈、堆
   → 易失性（掉电数据丢失）

② Flash（闪存）
   → 容量：512 KB
   → 起始地址：0x0800_0000
   → 用途：程序代码、常量数据
   → 非易失性（掉电不丢失）
```

### 1.2 片外可扩展存储器

```
开发板上可通过外部接口扩展多种存储设备：

① 外部 SRAM → 扩展内存容量
② NOR Flash → SPI 接口（如 W25Q32）
③ NAND Flash → 大容量存储
④ EEPROM → I²C 接口（如 AT24C02）
```

### 1.3 单片机 vs 个人电脑的内存结构

```
┌──────────────────────────────────────────────────┐
│  STM32 单片机：                                    │
│    → RAM 直接使用 SRAM                             │
│    → 容量小（64 KB），SRAM 速度更快                  │
│    → 结构简单，无需缓存层                           │
├──────────────────────────────────────────────────┤
│  个人电脑（PC）：                                   │
│    → RAM 使用 DRAM（容量大）                        │
│    → CPU 内部有多级 Cache（SRAM 做高速缓存）         │
│    → CPU ← L1/L2/L3 Cache ← 内存(DRAM)            │
└──────────────────────────────────────────────────┘

关键区别：
  STM32 容量小 → 直接用 SRAM 做内存（速度快）
  PC 容量大 → 用 DRAM 做内存（容量大）+ SRAM 做缓存
```

## 二、SRAM 访问方式

```
STM32 的 SRAM 支持不同位宽的访问方式：

  → 字节访问（8 位 / 1 字节）
  → 半字访问（16 位 / 2 字节）
  → 全字访问（32 位 / 4 字节）

三种方式均可直接对 SRAM 进行读写操作
```

## 三、存储器映射的概念

### 3.1 为什么需要存储器映射

```
问题：
  → CPU 需要访问各种存储单元
  → SRAM、Flash、外设寄存器……
  → 存储器本身没有地址信息
  → CPU 如何准确找到目标存储单元？

类比：
  → 一排房子没有门牌号 → 找人全靠"抓瞎"
  → 给每间房子分配门牌号 → 按门牌号就能找到
  → 存储器映射 = 给每个存储单元分配唯一的"门牌号"

结论：
  → 必须为所有存储区域分配统一的地址空间
  → 每个存储单元获得唯一的地址编码
  → CPU 通过地址即可准确定位目标存储单元
```

### 3.2 存储器映射的定义

```
存储器映射（Memory Map）：
  → 为每一个存储单元分配一个唯一的地址
  → 地址本质：无符号整数编码（十六进制表示）
  → STM32 地址宽度：32 位
  → 形成芯片理论上的完整地址空间

注意：
  → 存储器映射不只针对 SRAM 和 Flash
  → 所有片内外设的寄存器也需要映射地址
  → 所有需要 CPU 访问的存储单元都要参与映射
```

### 3.3 地址与存储单元的对应关系

```
存储器映射 = 建立"地址 ↔ 存储单元"的对应关系

  房子（存储单元）  ←→  门牌号（地址码）
  
  地址码 = 32 位无符号整数
  表示方式：十六进制（如 0x2000_0000）

  每一类存储器分配连续的一段地址：
  → SRAM 的所有存储单元 → 连续地址区间
  → Flash 的所有存储单元 → 连续地址区间
  → 某外设的所有寄存器 → 连续地址区间
  → 方便查找和管理
```

## 四、32 位地址空间

### 4.1 理论地址空间大小

```
32 位地址 → 可表示 2^32 个地址

计算：
  2^32 = 2^2 × 2^30
       = 4 × (2^10 × 2^10 × 2^10)
       = 4 × (1K × 1K × 1K)
       = 4 × 1G
       = 4 GB

地址范围：
  最小：0x0000_0000（32 个 0）
  最大：0xFFFF_FFFF（32 个 1）
  共计：4 GB 的地址空间
```

### 4.2 32 位与 64 位系统对比

```
32 位系统（早期电脑 / STM32）：
  → 地址空间 = 2^32 = 4 GB
  → 最大可访问 4 GB 内存
  → 超出 4 GB 的内存无法被 CPU 寻址
  → 相当于"门牌号不够分"

64 位系统（当前电脑）：
  → 地址空间 = 2^64
  → 理论上可访问的内存极其巨大
  → 内存扩展几乎没有上限

历史背景：
  → 早期电脑 CPU 为 32 位 → 最大支持 4 GB 内存
  → 这是当时电脑性能的重要瓶颈
  → 现在 CPU 和操作系统升级为 64 位 → 突破限制
```

## 五、小端存储格式

### 5.1 什么是小端存储

```
问题背景：
  → 一个 32 位数据占 4 个字节
  → 4 个字节有 4 个不同的地址
  → 低位字节存放在低地址还是高地址？

两种存储格式：

① 大端存储（Big Endian）
   → 低位字节存放在高地址
   → 高位字节存放在低地址
   → 从低地址读起：先看到高位 → 符合阅读习惯

② 小端存储（Little Endian）← STM32 和大多数计算机使用
   → 低位字节存放在低地址
   → 高位字节存放在高地址
   → 从低地址读起：先看到低位
```

### 5.2 存储示例

```
示例：uint32_t a = 1;

二进制表示：0x0000_0001
  → 低 8 位（最低有效字节）：0x01
  → 次低 8 位：0x00
  → 次高 8 位：0x00
  → 高 8 位（最高有效字节）：0x00

内存布局（小端存储）：

  地址      存储内容
  ┌──────────┬──────────┐
  │ 0x2004   │   0x01   │  ← 最低有效字节（低地址）
  ├──────────┼──────────┤
  │ 0x2005   │   0x00   │
  ├──────────┼──────────┤
  │ 0x2006   │   0x00   │
  ├──────────┼──────────┤
  │ 0x2007   │   0x00   │  ← 最高有效字节（高地址）
  └──────────┴──────────┘

如果是大端存储：
  地址      存储内容
  ┌──────────┬──────────┐
  │ 0x2004   │   0x00   │  ← 最高有效字节（低地址）
  ├──────────┼──────────┤
  │ 0x2005   │   0x00   │
  ├──────────┼──────────┤
  │ 0x2006   │   0x00   │
  ├──────────┼──────────┤
  │ 0x2007   │   0x01   │  ← 最低有效字节（高地址）
  └──────────┴──────────┘
```

### 5.3 为什么使用小端存储

```
小端存储的核心优势：方便数据类型转换

① uint32_t → uint8_t（32 位强转 8 位）
   → 直接取首地址对应的那 1 个字节即可
   → 无需管后续字节

② uint32_t → uint16_t（32 位强转 16 位）
   → 从首地址取 2 个字节即可
   → 低字节在首地址，高字节在首地址 +1

核心思想：
  → 找到首地址（最低地址）
  → 截取需要的字节数
  → 低位数据天然就在首地址处 → 最简单高效

注意：
  → 内存中数据的排列方式不影响最终读取结果
  → CPU 会按照存储格式正确还原数据
  → 我们看到的编程结果始终是正确的数值
```

## 六、STM32 存储器空间划分

### 6.1 八大 Block 总览

```
STM32 的 4 GB 地址空间划分为 8 个 Block：

  4 GB ÷ 8 = 0.5 GB = 512 MB = 512 Mb

  每个 Block 大小：512 MB（2^29 字节）

Block 划分：

  Block   地址范围                   用途
  ─────────────────────────────────────────────────
  Block 0  0x0000_0000 ~ 0x1FFF_FFFF  启动别名 / Flash / System Memory
  Block 1  0x2000_0000 ~ 0x3FFF_FFFF  SRAM
  Block 2  0x4000_0000 ~ 0x5FFF_FFFF  片内外设寄存器
  Block 3  0x6000_0000 ~ 0x7FFF_FFFF  FSMC Bank 1 & 2
  Block 4  0x8000_0000 ~ 0x9FFF_FFFF  FSMC Bank 3 & 4
  Block 5  0xA000_0000 ~ 0xBFFF_FFFF  FSMC 寄存器
  Block 6  0xC000_0000 ~ 0xDFFF_FFFF  未使用（保留）
  Block 7  0xE000_0000 ~ 0xFFFF_FFFF  Cortex-M3 内核外设

重点掌握：Block 0、Block 1、Block 2
```

### 6.2 地址范围计算方法

```
每个 Block 大小 = 512 MB = 2^29 字节

2^29 的十六进制表示：
  2^29 = 2 × 2^28
  2^28 = (2^4)^7 = 16^7 → 十六进制为 1 后面 7 个零 = 0x1000_0000
  2^29 = 2 × 0x1000_0000 = 0x2000_0000

因此每个 Block 占 0x2000_0000 的地址空间：

  Block 0：0x0000_0000 ~ 0x1FFF_FFFF
  Block 1：0x2000_0000 ~ 0x3FFF_FFFF
  Block 2：0x4000_0000 ~ 0x5FFF_FFFF
  ...以此类推
```

## 七、Block 0 详解 — 启动与 Flash

### 7.1 Block 0 的地址分布

```
Block 0（0x0000_0000 ~ 0x1FFF_FFFF）包含：

┌─────────────────────────────────────────────┐
│  启动别名区（Alias）                          │
│  0x0000_0000 ~ 0x0000_FFFF（或更大）          │
│  → 不直接存放数据                             │
│  → 是其他存储区域的"映射窗口"                  │
│  → 具体映射到谁取决于启动引脚（BOOT Pins）      │
├─────────────────────────────────────────────┤
│  Flash 存储器                                 │
│  0x0800_0000 ~ 0x0807_FFFF                   │
│  → 大小：512 KB                              │
│  → 存储程序代码和常量数据                      │
├─────────────────────────────────────────────┤
│  System Memory（系统存储器）                   │
│  0x1FFF_F000 ~ 0x1FFF_F7FF                   │
│  → 存储出厂预置的 Bootloader                   │
│  → 用于串口/USB 等方式烧写程序                 │
└─────────────────────────────────────────────┘
```

### 7.2 启动别名机制

```
为什么需要别名（Alias）？

  → STM32 上电后从地址 0x0000_0000 开始执行程序
  → 但 0x0000_0000 这个地址本身不直接存储数据
  → 它是其他存储区域的"别名"（映射窗口）
  → 具体映射到谁，由 BOOT 引脚决定

启动引脚（BOOT Pins）配置：

  BOOT1  BOOT0  启动方式              0x0000_0000 映射到
  ──────────────────────────────────────────────────────
    x      0     从 Flash 启动         Flash（0x0800_0000）
    0      1     从 System Memory 启动  System Memory
    1      1     从 SRAM 启动           SRAM（0x2000_0000）

正常运行（最常用）：
  → BOOT0 = 0
  → 0x0000_0000 映射到 Flash（0x0800_0000）
  → 上电后 CPU 从 Flash 中读取程序并执行

程序烧写（通过 ST-Link 等）：
  → 切换到 System Memory 启动
  → 执行出厂预置的 Bootloader
  → Bootloader 接收烧写数据并写入 Flash
  → 烧写完成后，切换回 Flash 启动
  → 下次上电直接从 Flash 运行用户程序
```

### 7.3 Flash 地址空间计算

```
Flash 地址范围：0x0800_0000 ~ 0x0807_FFFF

大小计算：
  0x0808_0000 - 0x0800_0000 = 0x0008_0000

  0x0800_0000 = 0x8 × 16^6 = 2^3 × (2^4)^6 = 2^3 × 2^24 = 2^27

  0x08_0000 = 2^19

  2^19 = 2^9 × 2^10 = 512 × 1K = 512 KB ✅

验证：与 STM32F103 数据手册标注的 Flash 容量一致
```

### 7.4 启动流程总结

```
正常启动流程：

  ① 上电 / 复位
  ② 检查 BOOT 引脚状态
  ③ 确定 0x0000_0000 映射到哪个存储区域
  ④ CPU 从 0x0000_0000 开始取指令执行
  ⑤ 如果映射到 Flash → 执行用户程序
  ⑥ 如果映射到 System Memory → 执行 Bootloader

ST-Link 烧写流程：

  ① ST-Link 控制 BOOT 引脚切换到 System Memory 启动
  ② CPU 执行 System Memory 中的 Bootloader
  ③ ST-Link 通过 SWD/JTAG 传输数据
  ④ Bootloader 将数据写入 Flash（0x0800_0000 起）
  ⑤ 烧写完成后，切换回 Flash 启动
  ⑥ 正常上电 → 从 Flash 运行用户程序
```

## 八、Block 1 详解 — SRAM

### 8.1 SRAM 地址空间

```
Block 1（0x2000_0000 ~ 0x3FFF_FFFF）主要包含：

┌─────────────────────────────────────────────┐
│  SRAM                                      │
│  0x2000_0000 ~ 0x2000_FFFF                 │
│  → 大小：64 KB                             │
│  → 存储运行时变量、栈、堆                    │
├─────────────────────────────────────────────┤
│  保留（Reserved）                           │
│  其余大量地址空间未使用                       │
└─────────────────────────────────────────────┘
```

### 8.2 SRAM 大小计算

```
SRAM 地址范围：0x2000_0000 ~ 0x2000_FFFF

大小计算：
  0x2001_0000 - 0x2000_0000 = 0x0001_0000

  0x1_0000 = 2^16 = 65536 字节 = 64 KB ✅

注意：
  → Block 1 总大小为 512 MB
  → SRAM 仅使用了其中 64 KB
  → 其余地址空间均为保留（Reserved）
```

## 九、Block 2 详解 — 片内外设

### 9.1 外设地址空间

```
Block 2（0x4000_0000 ~ 0x5FFF_FFFF）包含：

  → 所有片内外设的寄存器地址空间
  → 每个外设模块分配一段连续地址

外设基地址从 0x4000_0000 开始：

  外设模块          地址范围                   说明
  ──────────────────────────────────────────────────────
  GPIOA            0x4001_0800 ~ 0x4001_0BFF  GPIO 端口 A
  GPIOB            0x4001_0C00 ~ 0x4001_0FFF  GPIO 端口 B
  ...              ...                        ...
  DMA1             0x4002_0000 ~ 0x4002_03FF  DMA 控制器 1
  ...              ...                        ...
  SPI1             0x4001_3000 ~ 0x4001_33FF  SPI1
  SPI2             0x4000_3800 ~ 0x4000_3BFF  SPI2
  ...              ...                        ...
  USART1           0x4001_3800 ~ 0x4001_3BFF  USART1
  ...              ...                        ...

所有外设寄存器地址均可在数据手册中查到
```

### 9.2 外设寄存器地址说明

```
为什么外设寄存器有地址？

  → CPU 要读写外设的寄存器
  → 必须给每个寄存器分配地址
  → CPU 通过地址访问寄存器
  → 寄存器地址 = 属于存储器映射的一部分

地址使用方式：

  例：GPIOA 的起始地址 = 0x4001_0800
  
  GPIOA_CRL（端口配置低寄存器）= 基地址 + 0x00 = 0x4001_0800
  GPIOA_CRH（端口配置高寄存器）= 基地址 + 0x04 = 0x4001_0804
  GPIOA_IDR（输入数据寄存器）  = 基地址 + 0x08 = 0x4001_0808
  GPIOA_ODR（输出数据寄存器）  = 基地址 + 0x0C = 0x4001_080C
  ...

每个外设的寄存器都在其地址范围内，按偏移量排列
```

## 十、Block 3 & 4 — FSMC 存储器扩展

### 10.1 FSMC 概述

```
FSMC（Flexible Static Memory Controller）
  → 灵活的静态存储控制器
  → 用途：扩展外部存储器
  → 当片内存储不够时，可通过 FSMC 外接存储芯片

Block 3（0x6000_0000 ~ 0x7FFF_FFFF）：
  → FSMC Bank 1：NOR Flash / PSRAM（256 MB）
  → FSMC Bank 2：NAND Flash（256 MB）

Block 4（0x8000_0000 ~ 0x9FFF_FFFF）：
  → FSMC Bank 3：NAND Flash（256 MB）
  → FSMC Bank 4：PC Card（256 MB）
```

### 10.2 FSMC Bank 划分

```
Bank = 区（可理解为分区管理）

  Bank    大小      扩展设备
  ──────────────────────────────────
  Bank 1  256 MB    NOR Flash / PSRAM
  Bank 2  256 MB    NAND Flash
  Bank 3  256 MB    NAND Flash
  Bank 4  256 MB    PC Card

  → 通过 FSMC，CPU 可以像访问片内存储一样访问外部存储
  → 外部存储器地址映射到 Block 3 / Block 4
```

---

## 十一、Block 5 — FSMC 寄存器

```
Block 5（0xA000_0000 ~ 0xBFFF_FFFF）：

  → FSMC 模块自身的寄存器地址空间
  → 独立于其他外设（未放在 Block 2 中）
  → 用于配置 FSMC 的工作参数
  → 实际使用的地址空间非常有限
```

---

## 十二、Block 6 & 7

```
Block 6（0xC000_0000 ~ 0xDFFF_FFFF）：
  → 未使用，全部保留

Block 7（0xE000_0000 ~ 0xFFFF_FFFF）：
  → Cortex-M3 内核内部外设
  → 包括：
    → NVIC（嵌套向量中断控制器）
    → SysTick（系统定时器）
    → SCB（系统控制块）
    → MPU（内存保护单元）等
  → 属于 ARM Cortex-M3 内核私有外设
```

## 十四、关键概念速查

| 概念 | 说明 |
|------|------|
| 存储器映射 | 为每个存储单元分配唯一地址，建立"地址 ↔ 存储单元"对应关系 |
| 地址码 | 32 位无符号整数，标识唯一的存储单元 |
| 地址空间 | 32 位地址可寻址 4 GB 空间（2^32） |
| 小端存储 | 低位字节存放在低地址，STM32 和大多数计算机采用此格式 |
| 大端存储 | 低位字节存放在高地址，少数系统使用 |
| Block | STM32 将 4 GB 地址空间等分为 8 个 512 MB 的块 |
| Alias（别名） | 0x0000_0000 区域是其他存储区域的映射窗口 |
| BOOT Pins | 启动引脚，决定 0x0000_0000 映射到 Flash / System Memory / SRAM |
| Flash 地址 | 0x0800_0000 ~ 0x0807_FFFF（512 KB） |
| SRAM 地址 | 0x2000_0000 ~ 0x2000_FFFF（64 KB） |
| 外设基地址 | 从 0x4000_0000 开始（Block 2） |
| FSMC | 灵活静态存储控制器，用于外部存储器扩展（Block 3/4/5） |
| System Memory | 存储出厂 Bootloader，用于程序烧写 |
| Cortex-M3 内核外设 | 地址在 0xE000_0000 以上（Block 7），如 NVIC、SysTick |

## 十五、常见问题

| 问题 | 解答 |
|------|------|
| STM32 为什么用 SRAM 不用 DRAM 做内存？ | 容量小（64 KB），SRAM 速度更快且无需刷新电路 |
| Flash 地址从哪开始？ | **0x0800_0000**，大小 512 KB |
| SRAM 地址从哪开始？ | **0x2000_0000**，大小 64 KB |
| 为什么程序从 0x0800_0000 而不是 0x0000_0000 开始？ | 0x0000_0000 是别名区，BOOT=0 时映射到 Flash（0x0800_0000） |
| System Memory 有什么用？ | 存储出厂 Bootloader，用于通过串口/USB 烧写程序 |
| 什么是小端存储？ | 低位字节存放在低地址，方便数据类型转换（截取首地址即可） |
| 32 位地址空间有多大？ | 4 GB（2^32 字节） |
| 外设寄存器地址在哪找？ | Block 2（0x4000_0000 起），具体地址见数据手册 |
| FSMC 是什么？ | 灵活静态存储控制器，用于外接存储芯片扩展容量 |
| 存储器映射只针对 SRAM 和 Flash 吗？ | 不是，所有片内外设寄存器也参与映射 |
