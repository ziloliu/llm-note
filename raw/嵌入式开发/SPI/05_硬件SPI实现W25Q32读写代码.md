## 一、硬件 SPI vs 软件模拟 — 变化对比

### 1.1 不变的部分

```
硬件连接完全不变：
  CS   → PC13（GPIO 输出，片选）
  SCK  → PA5（SPI1_SCK）
  MOSI → PA7（SPI1_MOSI）
  MISO → PA6（SPI1_MISO）

上层接口完全不变：
  SPI_Init() / SPI_Start() / SPI_Stop() / SPI_SwapByte()
  → 函数签名和调用方式不变
  → W25Q32.c 中的所有代码完全不变
  → main.c 中的测试代码完全不变
```

### 1.2 变化的部分

| 项目 | 软件模拟 | 硬件 SPI |
|------|---------|---------|
| SCK 操作 | GPIO 拉高拉低 | **硬件自动输出** |
| MOSI 操作 | GPIO 拉高拉低 + 移位 | **硬件自动输出** |
| MISO 操作 | GPIO 读取 + 移位 | **硬件自动输入** |
| CS 操作 | GPIO 拉高拉低 | **GPIO 拉高拉低（不变）** |
| 延时 | SPI_DELAY() | **硬件自动控制** |
| SwapByte 实现 | GPIO 逐位翻转 | **读写 DR + 判断标志位** |

## 三、SPI.c 实现变化

### 3.1 初始化函数（变化最大）

```c
void SPI_Init(void)
{
    /* ======== 1. 开启时钟 ======== */
    RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;    // GPIOA 时钟
    RCC->APB2ENR |= RCC_APB2ENR_IOPCEN;    // GPIOC 时钟
    RCC->APB2ENR |= RCC_APB2ENR_SPI1EN;    // SPI1 时钟 ← 新增！

    /* ======== 2. 配置 GPIO 工作模式 ======== */

    /* PC13 → 通用推挽输出（片选 CS）— 不变 */
    GPIOC->CRH |= GPIO_CRH_MODE13;
    GPIOC->CRH &= ~GPIO_CRH_CNF13;

    /* PA5 → 复用推挽输出（SPI1_SCK）← 变化！ */
    GPIOA->CRL |= GPIO_CRL_MODE5;           // MODE = 11
    GPIOA->CRL |= GPIO_CRL_CNF5_1;          // CNF = 10（复用推挽）
    GPIOA->CRL &= ~GPIO_CRL_CNF5_0;

    /* PA7 → 复用推挽输出（SPI1_MOSI）← 变化！ */
    GPIOA->CRL |= GPIO_CRL_MODE7;           // MODE = 11
    GPIOA->CRL |= GPIO_CRL_CNF7_1;          // CNF = 10（复用推挽）
    GPIOA->CRL &= ~GPIO_CRL_CNF7_0;

    /* PA6 → 浮空输入（SPI1_MISO）— 不变 */
    GPIOA->CRL &= ~GPIO_CRL_MODE6;
    GPIOA->CRL = (GPIOA->CRL & ~GPIO_CRL_CNF6) | GPIO_CRL_CNF6_0;

    /* ======== 3. 配置 SPI CR1 ======== */

    /* 3.1 主模式 */
    SPI1->CR1 |= SPI_CR1_MSTR;              // Bit 2 = 1

    /* 3.2 软件片选（主模式，NSS 拉高）*/
    SPI1->CR1 |= SPI_CR1_SSM;               // Bit 9 = 1
    SPI1->CR1 |= SPI_CR1_SSI;               // Bit 8 = 1

    /* 3.3 工作模式 0（CPOL=0, CPHA=0）*/
    SPI1->CR1 &= ~SPI_CR1_CPOL;             // Bit 1 = 0（空闲低电平）
    SPI1->CR1 &= ~SPI_CR1_CPHA;             // Bit 0 = 0（第一个跳变沿采样）

    /* 3.4 波特率 4 分频（72MHz / 4 = 18MHz）*/
    SPI1->CR1 &= ~SPI_CR1_BR;               // BR 清零
    SPI1->CR1 |= SPI_CR1_BR_0;              // BR = 001（4 分频）

    /* 3.5 数据帧格式 8 位（默认值）*/
    SPI1->CR1 &= ~SPI_CR1_DFF;              // Bit 11 = 0

    /* 3.6 MSB 先行（默认值）*/
    SPI1->CR1 &= ~SPI_CR1_LSBFIRST;         // Bit 7 = 0

    /* ======== 4. 使能 SPI ======== */
    SPI1->CR1 |= SPI_CR1_SPE;               // Bit 6 = 1
}
```

### 3.2 GPIO 配置变化详解

```
软件模拟时：
  PA5(SCK)  → 通用推挽输出：MODE=11, CNF=00
  PA7(MOSI) → 通用推挽输出：MODE=11, CNF=00
  PA6(MISO) → 浮空输入：    MODE=00, CNF=01

硬件 SPI 时：
  PA5(SCK)  → 复用推挽输出：MODE=11, CNF=10  ← CNF 从 00 变为 10
  PA7(MOSI) → 复用推挽输出：MODE=11, CNF=10  ← CNF 从 00 变为 10
  PA6(MISO) → 浮空输入：    MODE=00, CNF=01  ← 不变

  PC13(CS)  → 通用推挽输出：MODE=11, CNF=00  ← 不变

原因：
  → 通用输出：CPU 直接控制 GPIO 输出电平
  → 复用输出：由片上外设（SPI1）控制 GPIO 输出电平
  → 浮空输入：通用和复用输入模式相同（CNF=01）
```

### 3.4 SwapByte 函数（变化最大）

```c
uint8_t SPI_SwapByte(uint8_t byte)
{
    /* === 第一步：将数据写入发送缓冲区 === */

    /* 1.1 等待发送缓冲区为空（TXE=1）*/
    while (!(SPI1->SR & SPI_SR_TXE));    // TXE=0 则等待

    /* 1.2 写入数据到 DR（启动发送）*/
    SPI1->DR = byte;

    /* === 第二步：读取接收缓冲区的数据 === */

    /* 2.1 等待接收缓冲区非空（RXNE=1）*/
    while (!(SPI1->SR & SPI_SR_RXNE));   // RXNE=0 则等待

    /* 2.2 从 DR 读取接收到的数据 */
    return (uint8_t)(SPI1->DR & 0xFF);   // 16 位 DR 截取低 8 位
}
```

### 3.5 SwapByte 核心逻辑

```
与软件模拟的本质区别：

软件模拟（逐位操作）：
  for (8 次) {
      准备 MOSI 输出 → 拉高 SCK → 读取 MISO → 拉低 SCK
  }

硬件 SPI（标志位轮询）：
  等待 TXE=1 → 写 DR → 等待 RXNE=1 → 读 DR
  （硬件自动完成 8 位的逐位发送和接收）

DR 寄存器注意事项：
  → DR 是 16 位寄存器
  → 我们只用 8 位数据帧格式
  → 返回时需 & 0xFF 截取低 8 位
  → 可加强制类型转换 (uint8_t) 明确意图
```

## 五、SR 状态寄存器标志位

```
轮询方式需要判断的两个标志位：

① TXE（SR Bit 1）— 发送缓冲区空
   = 0：发送缓冲区非空（还有数据未发出）
   = 1：发送缓冲区为空（可以写入新数据）
   → 写 DR 时自动清零

② RXNE（SR Bit 0）— 接收缓冲区非空
   = 0：接收缓冲区空（没有数据可读）
   = 1：接收缓冲区非空（有数据可读）
   → 读 DR 时自动清零

用法：
  while (!(SPI1->SR & SPI_SR_TXE));   // 等待 TXE=1
  while (!(SPI1->SR & SPI_SR_RXNE));  // 等待 RXNE=1
```

## 七、软件模拟 vs 硬件 SPI 代码对比

### 7.1 SwapByte 对比

```c
/* ========== 软件模拟 ========== */
uint8_t SPI_SwapByte(uint8_t byte)
{
    uint8_t rByte = 0x00;
    for (int i = 0; i < 8; i++) {
        // 准备发送
        if (byte & 0x80) MOSI_HIGH();
        else             MOSI_LOW();
        byte <<= 1;
        // 拉高时钟
        SCK_HIGH();
        SPI_DELAY();
        // 读取接收
        rByte <<= 1;
        if (MISO_READ()) rByte |= 0x01;
        // 拉低时钟
        SCK_LOW();
        SPI_DELAY();
    }
    return rByte;
}

/* ========== 硬件 SPI ========== */
uint8_t SPI_SwapByte(uint8_t byte)
{
    while (!(SPI1->SR & SPI_SR_TXE));  // 等待发送空
    SPI1->DR = byte;                    // 写入发送
    while (!(SPI1->SR & SPI_SR_RXNE)); // 等待接收满
    return (uint8_t)(SPI1->DR & 0xFF); // 读取接收
}
```

## 九、配置顺序要点

```
正确的配置顺序：

① 开时钟（GPIO + SPI1）
② 配 GPIO 工作模式（复用推挽/浮空输入/通用推挽）
③ 配 SPI CR1：
   a. MSTR（主模式）← 先配
   b. SSM + SSI（软件片选）
   c. CPOL + CPHA（Mode 0）
   d. BR（波特率）
   e. DFF（数据帧格式）
   f. LSBFIRST（位序）
   g. SPE（使能）← 最后开启！

⚠️ SPE 必须最后配置！
  → SPE=1 后 SPI 开始工作
  → 之后再改 CR1 其他位可能导致错误
  → 先配完所有参数，最后开启
```

## 十、常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| SPI 无时钟输出 | SPI1 时钟未开 | 开启 RCC_APB2ENR_SPI1EN |
| 引脚无输出 | CNF 配置错误 | 改为复用推挽（CNF=10） |
| 数据全错 | SPE 先于其他配置 | SPE 最后配置 |
| 一直等 TXE | SPI 未使能 | 检查 SPE 位 |
| 一直等 RXNE | 从设备无响应 | 检查 CS 和接线 |
| 返回数据少一位 | DR 是 16 位 | & 0xFF 截取低 8 位 |
| W25Q32 不工作 | 两种实现不一致 | 确认链接的是新 SPI.c |
| 编译报错 | 未添加 SPI1 时钟 | 检查 RCC 配置 |
