# 第七章 LCD（液晶显示器）— 液晶模块与控制器详解 笔记

---

## 一、TFT LCD 概述

### 1.1 什么是 TFT LCD

```
TFT = Thin Film Transistor（薄膜晶体管）
TFT LCD = 薄膜晶体管液晶显示器

原理：
  → 每个像素点由薄膜晶体管驱动
  → 将电信号（RGB 数据）转换为对薄膜晶体管的控制
  → 薄膜晶体管驱动像素点显示不同颜色

特点：
  → 优秀的显示性能（颜色、对比度、亮度）
  → 低功耗
  → 广泛应用于嵌入式电子设备
  → 当前嵌入式设备中使用最广泛的液晶显示技术
```

## 二、Z350IT002 液晶模块

### 2.1 基本参数

| 参数 | 值 |
|------|-----|
| 型号 | Z350IT002 |
| 类型 | TFT LCD（薄膜晶体管液晶显示器） |
| 分辨率 | **320 × 480** |
| 横向像素 | 320 个 |
| 纵向像素 | 480 个 |
| 接口模式 | **MCU 模式**（I80 / 8080 总线标准） |
| 数据宽度 | **16 位** |
| 控制器芯片 | **ILI9486** |

### 2.2 分辨率说明

```
320 × 480 分辨率：

  横向：320 个像素点（列）
  纵向：480 个像素点（行）

  总像素数：320 × 480 = 153600 个像素点

  相当于早期标清视频的分辨率
  → 能够显示比较清晰的图像和文字
  → 适合中小尺寸的嵌入式显示需求
```

### 2.3 底层驱动结构

```
驱动电路组成：
  → 960 个 Source（源极）驱动
  → 480 个 Gate（栅极）驱动

对应关系：
  → 480 个 Gate = 480 行（纵向 480 个像素点）
  → 960 个 Source = 320 列 × 3（每列 3 个 RGB 子像素）
  → 每个像素点由 R、G、B 三个子像素组成
  → 3 个 Source 驱动 1 个像素点的 3 个子像素

底层本质：
  → Source = 晶体管的源极（Source）
  → Gate = 晶体管的栅极（Gate）
  → 用薄膜晶体管阵列驱动 320×480 的像素点矩阵
```

### 2.4 应用领域

```
适合的应用场景：
  → 便携式嵌入式设备
  → 工业控制面板
  → 小型嵌入式系统
  → 中小尺寸显示需求

优势：
  → 易于微控制器集成和控制
  → 颜色、对比度、亮度表现优秀
  → 适合中等分辨率和高色彩质量的应用
```

## 三、ILI9486 液晶控制器芯片

### 3.1 芯片概述

```
芯片名称：ILI9486
制造商：台湾 ILITEC（伊利科技）公司
定位：最流行的 LCD 控制器芯片之一

功能：
  → 驱动中小型尺寸的 TFT LCD
  → 支持分辨率：320 × 480
  → 内含源极驱动器（Source Driver）和栅极驱动器（Gate Driver）
  → 内含显存（GRAM）
  → 支持多种接口类型
```

### 3.2 支持的接口类型

```
ILI9486 支持的接口类型：

① 并行 CPU 数据总线接口（8080 总线标准）
   → 支持 8 位、9 位、16 位、18 位数据宽度
   → MCU 模式

② RGB 标准数据总线
   → 用于视频图像展示
   → RGB 模式

③ SPI 串行外设接口
   → 支持 3 线和 4 线 SPI
   → 串行数据传输

④ 高速串行接口
   → 支持 MIPI DSI 链路
   → 最高 500 Mbps

⑤ MDDI 接口
   → Mobile Display Digital Interface

我们使用的方式：
  → IM[2:0] = 010
  → 8080 总线标准（MCU 模式）
  → 16 位数据总线宽度
  → 数据引脚 D[15:0]
```

### 3.3 接口选择（IM 位配置）

```
ILI9486 通过 IM[2:0] 引脚选择接口模式：

  IM[2:0]    接口类型
  ────────────────────────────────
  000        并行 RGB
  001        串行 RGB
  010        8080 系统接口（16 位）← 我们使用这个
  011        保留
  100        3 线 SPI（9 位）
  101        3 线 SPI（16 位）
  110        4 线 SPI（8 位）
  111        4 线 SPI（16 位）

硬件上 IM 引脚已固定为 010：
  → 确定使用 8080 系统接口
  → 16 位数据总线
  → 数据引脚 D[15:0]
```

## 四、MCU 模式与 8080 总线标准

### 4.1 MCU 模式的本质

```
MCU 模式的核心特征：
  → 显存（GRAM）集成在液晶控制器内部
  → MCU（单片机）只需发送命令和数据
  → 控制器接收数据 → 写入内部 GRAM → 驱动显示

为什么叫 MCU 模式：
  → 最早由 Intel 提出的 8080 总线标准
  → 专为微控制器（MCU）设计
  → MCU 操作简单，适合资源有限的单片机
  → 因此称为 MCU 模式 / I80 模式 / 8080 时序
```

### 4.2 8080 总线标准

```
8080 总线标准（Intel 8080 Bus Standard）：
  → 最早由 Intel 提出
  → 用于微处理器与外部设备之间的并行数据传输
  → 并行地址线 + 数据线 + 控制信号

核心信号：
  → CS：片选信号
  → RS：寄存器选择（命令/数据选择）
  → RD：读使能
  → WR：写使能
  → D[15:0]：16 位数据总线

与 FSMC 的对应关系：
  → 8080 总线标准 ≈ FSMC 扩展存储器的方式
  → 可以直接用 FSMC 实现 8080 时序
  → 无需手动编写通信协议
```

### 4.3 用 FSMC 实现 8080 时序

```
核心思路：
  → 将 LCD 的显存（GRAM）视为一个扩展的存储器
  → 使用 FSMC 连接 LCD 模块
  → CPU 像访问内存一样访问 LCD

连接方式：
  → LCD 的数据线 D[15:0] → FSMC 数据线
  → LCD 的 CS → FSMC NE（片选）
  → LCD 的 RS → FSMC A10（命令/数据选择）
  → LCD 的 RD → FSMC NOE（读使能）
  → LCD 的 WR → FSMC NWE（写使能）

地址映射：
  → 写命令地址：A10 = 0 → 0x6C00_0000
  → 写数据地址：A10 = 1 → 0x6C00_0800

操作方式：
  → 写命令：*(volatile uint16_t *)0x6C000000 = command;
  → 写数据：*(volatile uint16_t *)0x6C000800 = data;
```

## 五、ILI9486 命令操作

### 5.1 命令与数据的交互

```
ILI9486 的操作方式（类似 Flash/W25Q32 的指令交互）：

  → 先发送命令码（告诉控制器要做什么操作）
  → 再发送数据（操作的具体参数或颜色数据）

常见操作：
  → 设置显示区域（窗口）
  → 设置 GRAM 写入坐标
  → 写入像素颜色数据
  → 配置显示参数（方向、颜色格式等）
  → 读取状态/数据

命令码在芯片手册第 8 章有详细定义
```

### 5.2 区域写入操作

```
ILI9486 支持指定显示区域后连续写入数据：

  ① 发送命令设置窗口范围
     → 指定起始行、结束行、起始列、结束列
     → 定义要写入的矩形区域

  ② 发送写入 GRAM 命令
     → 通知控制器接下来发送的是颜色数据

  ③ 连续发送颜色数据
     → 每个数据对应一个像素点的颜色
     → GRAM 地址自动递增
     → 按行优先顺序填充整个区域

效果：
  → 不需要逐个像素点指定坐标
  → 一次设置区域，连续写入数据
  → 控制器自动管理 GRAM 地址
  → 操作简单高效
```

## 六、RGB565 颜色格式

### 6.1 为什么用 16 位表示颜色

```
16 位数据总线 → 每次传输 16 位数据

16 位需要分配给 R、G、B 三种颜色：

  → 16 ÷ 3 = 5.33... 无法均分
  → 解决方案：5 + 6 + 5 = 16 位

为什么绿色多一位？
  → 人眼对绿色最敏感
  → 可见光谱中绿色处于中间频率段
  → 人眼对绿色的捕获能力最强
  → 给绿色多分配 1 位 → 更细腻的绿色层次
```

### 6.2 RGB565 格式定义

```
RGB565 格式（16 位）：

  位    [15:11]    [10:5]    [4:0]
  颜色    R          G         B
  位数    5 位       6 位      5 位

  ┌─────┬────────┬─────┐
  │ RRRRR │ GGGGGG │ BBBBB │
  │ 5 位  │  6 位  │ 5 位  │
  └─────┴────────┴─────┘

颜色表示能力：
  → 红色：2^5 = 32 级
  → 绿色：2^6 = 64 级
  → 蓝色：2^5 = 32 级
  → 总颜色数：32 × 64 × 32 = 65536 种颜色
  → 也称为 65K 色或 16 位真彩色
```

### 6.3 常见颜色的 RGB565 值

```
颜色        R(5位)  G(6位)  B(5位)    RGB565 值
────────────────────────────────────────────────
白色        11111   111111  11111     0xFFFF
黑色        00000   000000  00000     0x0000
红色        11111   000000  00000     0xF800
绿色        00000   111111  00000     0x07E0
蓝色        00000   000000  11111     0x001F
黄色        11111   111111  00000     0xFFE0
青色        00000   111111  11111     0x07FF
品红        11111   000000  11111     0xF81F
```

### 6.4 颜色值计算方法

```
将 RGB888（24 位）转换为 RGB565（16 位）：

  RGB888：R[7:0] G[7:0] B[7:0]（每色 8 位，共 24 位）
  RGB565：R[4:0] G[5:0] B[4:0]（共 16 位）

转换公式：
  R5 = R8 >> 3（取高 5 位）
  G6 = G8 >> 2（取高 6 位）
  B5 = B8 >> 3（取高 5 位）

  RGB565 = (R5 << 11) | (G6 << 5) | B5

示例：纯红色 (255, 0, 0)
  R5 = 255 >> 3 = 31 = 0x1F
  G6 = 0 >> 2 = 0
  B5 = 0 >> 3 = 0
  RGB565 = (0x1F << 11) | (0 << 5) | 0 = 0xF800
```

## 七、系统整体架构

### 7.1 完整控制链路

```
┌──────────┐   AHB 总线   ┌───────┐   地址/数据/控制线   ┌──────────────┐
│  STM32   │──────────────→│ FSMC  │────────────────────→│ ILI9486      │
│  (CPU)   │              │       │                      │ (LCD 控制器)  │
└──────────┘              └───────┘                      ├──────────────┤
                                                         │  GRAM (显存)  │
                                                         ├──────────────┤
                                                         │ 源极/栅极驱动 │
                                                         ├──────────────┤
                                                         │  TFT LCD 面板 │
                                                         │  320 × 480    │
                                                         └──────────────┘

控制流程：
  ① CPU 通过 AHB 总线发送地址和数据
  ② FSMC 转换为 8080 总线协议
  ③ 通过地址线、数据线、控制线连接 ILI9486
  ④ ILI9486 接收命令/数据，写入内部 GRAM
  ⑤ ILI9486 从 GRAM 读取数据
  ⑥ 源极/栅极驱动器驱动 TFT LCD 面板显示
```

### 7.2 FSMC 与 LCD 的连接信号

```
FSMC 信号           LCD（ILI9486）信号    功能
──────────────────────────────────────────────────
D[15:0]       ←→    D[15:0]             16 位数据线
NE            ──→    CS                  片选信号（低有效）
A10           ──→    RS                  命令/数据选择
NOE           ──→    RD                  读使能（低有效）
NWE           ──→    WR                  写使能（低有效）

RS（寄存器选择）：
  → RS = 0（A10 = 0）→ 传输命令
  → RS = 1（A10 = 1）→ 传输数据
```

### 7.3 地址映射

```
连接到 Bank 1 的某个子区（如 NE4）：

  写命令地址：0x6C00_0000（A10 = 0 → RS = 0）
  写数据地址：0x6C00_0800（A10 = 1 → RS = 1）

操作方式：
  // 发送命令
  *(volatile uint16_t *)0x6C000000 = 0x002C;  // 写 GRAM 命令

  // 写入像素颜色数据
  *(volatile uint16_t *)0x6C000800 = 0xF800;  // 红色
  *(volatile uint16_t *)0x6C000800 = 0x07E0;  // 绿色
  *(volatile uint16_t *)0x6C000800 = 0x001F;  // 蓝色

效果：
  → CPU 认为自己在访问内存
  → FSMC 自动转换为 8080 协议
  → ILI9486 接收命令和数据
  → 数据写入 GRAM → 驱动像素显示
```

## 八、与扩展 SRAM 的对比

### 8.1 相同点

```
FSMC 扩展 SRAM vs FSMC 控制 LCD：

相同点：
  → 都使用 FSMC 进行地址映射
  → 都通过地址线、数据线、控制线连接
  → 都使用 16 位数据宽度
  → CPU 都像访问内存一样操作
  → 都位于 Bank 1 的某个子区
  → GPIO 配置方式相同（复用推挽输出）
  → BCR/BTR 寄存器配置方式相同
```

### 8.2 不同点

```
不同点：
  → SRAM 是真正的存储器，LCD 的 GRAM 是显存
  → SRAM 直接存储数据，LCD 需要先发命令再发数据
  → LCD 有 RS 信号（命令/数据选择），SRAM 没有
  → LCD 通过 A10 区分命令和数据，SRAM 不需要
  → LCD 最终驱动像素显示，SRAM 纯粹存储数据
```
